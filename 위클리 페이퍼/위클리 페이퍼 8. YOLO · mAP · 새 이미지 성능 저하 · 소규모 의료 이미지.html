실습 해설

YOLO(You Only Look Once) 모델의 주요 특징과 장점은 무엇인가요?

한 줄 요약

YOLO는 이미지 전체를 신경망 순전파 한 번으로 처리해, 모든 위치의 바운딩 박스 · 객체 신뢰도 · 클래스 확률을 동시에 예측하는 one-stage 객체 탐지기다. 후보 영역을 먼저 만들고 하나씩 분류하는 R-CNN 계열과 달리, 탐지를 하나의 회귀 문제로 풀기 때문에 빠르다.

  • 장점: 실시간 속도, 이미지 전체 문맥을 봐서 배경 오탐이 적음, 입력부터 출력까지 하나의 네트워크로 학습
  • 약점(원조 v1 기준): 박스 위치 오차, 한 셀에 몰린 작은 객체 · 겹친 객체

이후 버전들은 다중 스케일 예측, 앵커 → 앵커 프리, NMS 제거로 이 약점을 줄여 왔고, 2026년 지금도 여러 팀이 새 번호를 내고 있다.

실험 2 신뢰도 임계값과 NMS 임계값 예시 예측 · 사람 6명

탐지기는 같은 사람 주변에 박스를 여러 개 냅니다. 후처리는 두 단계입니다.

  • 신뢰도 임계값: 점수가 낮은 박스를 버린다
  • NMS(Non-Maximum Suppression): 점수가 가장 높은 박스를 남기고, 그 박스와 IoU가 임계값을 넘는 박스를 지운다. 이것을 남은 박스에 반복한다.

남은 박스는 정답과 IoU 0.5 이상이면 TP, 아니면 FP입니다. 한 사람에게 이미 TP가 있으면 두 번째 박스는 중복 FP입니다. 사람끼리 가까울수록 이웃 정답 박스끼리의 IoU가 커져, NMS가 다른 사람의 박스까지 지우기 시작합니다.

번호가 크다고 같은 팀의 후속작이거나 항상 더 좋은 것은 아닙니다. 고를 때는 공개 벤치마크보다 내 데이터의 mAP와 내 장비의 지연 시간을 직접 재야 합니다.

Ultralytics · 사전 학습 YOLO로 바로 추론하기
from ultralytics import YOLO

model = YOLO("yolo11n.pt")              # COCO로 사전 학습된 가장 작은 모델
results = model.predict("street.jpg",
                        imgsz=640,      # 작은 객체가 많으면 키운다
                        conf=0.25,      # 신뢰도 임계값 (기본값)
                        iou=0.7)        # NMS IoU 임계값 (기본값)
for box in results[0].boxes:
    print(model.names[int(box.cls)], float(box.conf), box.xyxy.tolist())

model.train(data="my_data.yaml", epochs=100, imgsz=640)   # 내 데이터로 미세 조정
torchvision · IoU와 NMS를 직접 계산하기
import torch
from torchvision.ops import box_iou, nms

boxes = torch.tensor([[100., 80., 160., 230.],   # (x1, y1, x2, y2)
                      [104., 84., 162., 236.],   # 같은 사람에 대한 중복 예측
                      [130., 82., 190., 232.]])  # 바로 옆 사람
scores = torch.tensor([0.92, 0.85, 0.80])

print(box_iou(boxes[:1], boxes))   # tensor([[1.0000, 0.8481, 0.3274]])
print(nms(boxes, scores, iou_threshold=0.5))   # tensor([0, 2])
print(nms(boxes, scores, iou_threshold=0.3))   # tensor([0]) · 옆 사람까지 지워짐
2 · 핵심 정리와 보충
정정 · 실습 해설에서 바로잡을 부분
원래 · 실습 해설이미지 전체를 작은 그리드로 나누고, 각 그리드 셀에서 객체의 중심이 존재할 가능성을 예측하는 방식으로 동작합니다.

정정셀이 예측하는 것은 "중심이 있을 가능성" 하나가 아닙니다. YOLOv1의 셀은 다음을 함께 냅니다.

  • 박스 B개(v1은 2개)마다 x, y, w, h와 신뢰도 c = Pr(객체) × IoU(예측, 정답)
  • 클래스 C개에 대한 조건부 확률 Pr(클래스 | 객체)

"중심"은 학습 때 어느 셀이 그 객체를 맡을지 정하는 규칙입니다. 최종 점수는 두 값을 곱한 클래스별 신뢰도입니다.

원래 · 실습 해설다른 객체 탐지 모델(R-CNN 계열)과 비교했을 때, YOLO는 몇 배 이상 빠르게 동작하면서도 상대적으로 높은 정확도를 유지합니다.

정정원 논문에서 YOLO는 Faster R-CNN(VGG-16)보다 약 6배 빨랐지만 mAP는 약 10%p 낮았습니다(63.4 vs 73.2). 논문 스스로도 정확도, 특히 위치 정확도에서 뒤진다고 밝혔습니다.

"속도와 정확도의 교환에서 실시간 쪽을 택한 모델"이 정확한 표현이고, 지금의 속도 비교는 모델 크기 · 입력 해상도 · 하드웨어를 맞춘 상태에서만 의미가 있습니다.

원래 · 실습 해설최신 버전(YOLOv3, YOLOv4, YOLOv5 등)에서 개선이 이루어지고 있습니다. 최신 버전에서는 앵커 박스(anchor box) 활용, 더 깊어진 네트워크 구조, 고해상도 입력 지원 등의 기술을 통해 정확도를 향상시키고 있습니다.

정정두 가지가 현재와 맞지 않습니다.

  • 최신 버전: v3~v5는 2018~2020년 모델입니다. 2026년 10월 기준으로는 YOLO11(2024), YOLOv12(2025), YOLO26(2026.01 정식 출시 발표) 등이 나와 있고, 만든 곳도 서로 다릅니다.
  • 앵커 박스: 앵커는 v2(2016)에서 도입된 오래된 기법이고, YOLOX(2021) · YOLOv8(2023) 이후 주류는 오히려 앵커 프리입니다. 최근의 큰 변화는 NMS를 없앤 끝단 간 예측(YOLOv10, YOLO26)입니다.
원래 · 실습 해설YOLO는 엔드투엔드 방식(end-to-end approach)을 사용하여 모델이 이미지에서 직접 바운딩 박스와 클래스를 예측합니다.

정정학습은 하나의 네트워크로 끝까지 이루어지지만, YOLOv1부터 YOLO11까지 대부분은 추론 뒤에 NMS라는 별도의 후처리가 필요했습니다(실험 2). 후처리까지 없앤 의미의 엔드투엔드는 YOLOv10 · YOLO26 같은 최근 모델에 해당합니다.

보충 · 작성 답안 확인

핵심 판단이 정확하다

작성 답안의 "한 번 본다 = 객체마다 신경망을 따로 돌리지 않는다", "그리드 설명은 모든 버전에 그대로 맞지 않는다", "항상 몇 배 빠르다는 단정 금지", "YOLO 번호는 단일 계보가 아니다"는 모두 맞습니다.

덧붙일 점은 현대 YOLO도 특징 맵의 각 위치에서 예측한다는 점에서 격자 개념은 남아 있다는 것입니다. 바뀐 것은 다음 세 가지입니다.

  • 격자가 여러 해상도(stride 8 · 16 · 32)로 늘었다
  • "중심이 든 셀 하나가 담당" 대신 예측 품질로 정답을 배정하는 동적 배정(TAL 등)을 쓴다
  • 앵커 대신 위치에서 박스 경계까지의 거리를 직접 예측한다(앵커 프리)
보충 · 작은 객체와 군중에 대응하는 실무 방법

모델 교체보다 먼저 할 일

  • 입력 해상도 올리기: 입력 한 변을 2배(예: 640 → 1280) 키우면 작은 객체가 stride 8 격자에서 4배 많은 픽셀을 차지합니다. 대신 계산량도 약 4배입니다.
  • 타일링: 고해상도 항공 · 위성 사진은 잘라서 추론한 뒤 합칩니다.
  • NMS 임계값 조정: 군중 장면은 IoU 임계값을 너무 낮추면 이웃 사람이 지워집니다(실험 2).
  • 크기별 mAP 확인: 전체 mAP 대신 작은 객체의 AP를 따로 봅니다(Q2).

YOLO는 객체 후보 영역을 따로 만들지 않고, 하나의 신경망이 이미지 전체를 한 번 순전파해서 모든 위치의 바운딩 박스, 객체 신뢰도, 클래스 확률을 동시에 예측하는 one-stage 탐지기입니다.

장점은 세 가지입니다. 구조가 통합돼 있어 실시간 처리가 가능하고, 이미지 전체 문맥을 보기 때문에 배경 오탐이 적고, 입력부터 출력까지 하나의 네트워크로 학습합니다. 대신 원조 YOLO는 Faster R-CNN보다 6배쯤 빠른 대신 mAP가 10%p 정도 낮았고, 셀마다 박스 두 개만 내서 작은 객체 무리와 위치 정확도에 약했습니다.

이후 버전은 다중 스케일 예측, 앵커 프리, NMS 없는 끝단 간 예측으로 이 약점을 줄여 왔습니다. 실무에서는 버전 번호보다 내 데이터의 mAP와 장비의 지연 시간을 직접 재서 고르고, 작은 객체가 많으면 입력 해상도와 크기별 AP를 함께 보겠습니다.

퀴즈 자가 점검

Q2
실습 해설

mAP(mean Average Precision)의 개념이 무엇이며 객체 인식에서 어떻게 활용되는지 설명해주세요.

한 줄 요약

mAP는 클래스별 AP(Average Precision)를 평균한 값이다. AP는 한 클래스의 예측을 신뢰도 순으로 정렬해 하나씩 TP · FP로 판정하며 그린 Precision–Recall 곡선을 하나의 숫자로 요약한 것이고, TP 판정에는 IoU 기준이 들어간다.

  • mAP@50 (VOC 방식): IoU 0.5 이상이면 맞음 → 객체를 찾았는가
  • mAP@[.50:.95] (COCO 방식): IoU 0.50~0.95, 10개 기준의 평균 → 박스까지 정확한가

그래서 mAP 숫자는 어떤 데이터셋 · 어떤 IoU 기준 · 어떤 보간 방식인지와 함께 말해야 비교할 수 있다.

1 · 그림·표·실험

핵심 계산에 들어가는 네 가지 식

IoU = |예측 ∩ 정답| / |예측 ∪ 정답|
Precision = TP / (TP + FP) ,   Recall = TP / (TP + FN) = TP / 정답 객체 수
AP = ∫01 pinterp(r) dr ,   pinterp(r) = maxr′ ≥ r p(r′)
mAP = (AP1 + AP2 + … + APN) / N

탐지에서는 TN(배경을 배경이라 맞힌 것)을 셀 수 없습니다. 배경 위치는 사실상 무한하기 때문입니다. 그래서 Accuracy나 ROC 대신 TN이 필요 없는 Precision–Recall로 평가합니다.

pinterp는 "그 재현율 이상에서 얻을 수 있는 가장 높은 정밀도"로 곡선을 감싼 것입니다. 지그재그 곡선을 계단 모양으로 펴서, 예측 순서의 작은 흔들림에 AP가 덜 민감하게 만듭니다.

직접 구현 · 모든 점 보간 AP (TP 판정은 끝난 상태)
import numpy as np

def average_precision(scores, is_tp, n_gt):
    order = np.argsort(-scores)                  # 신뢰도 높은 순
    tp = np.cumsum(is_tp[order])
    fp = np.cumsum(~is_tp[order])
    recall = tp / n_gt
    precision = tp / (tp + fp)
    r = np.concatenate([[0], recall, [1]])
    p = np.concatenate([[0], precision, [0]])
    p = np.maximum.accumulate(p[::-1])[::-1]     # 오른쪽 최댓값으로 감싸기
    return np.sum((r[1:] - r[:-1]) * p[1:])

정정 · 실습 해설에서 바로잡을 부분
원래 · 실습 해설일반적으로 IoU가 특정 임계값(예: 0.5) 이상이면 정확한 탐지로 간주하고, Precision과 Recall을 계산한 후 AP를 산출합니다.

정정빠진 단계가 두 가지 있어서 이 설명대로 계산하면 AP가 실제보다 높게 나옵니다.

  • 신뢰도 순 정렬: Precision · Recall은 한 번만 계산하는 값이 아니라, 신뢰도 순으로 예측을 하나씩 추가하며 매번 다시 계산한 곡선입니다.
  • 정답당 TP는 하나: IoU가 0.5를 넘어도 이미 짝이 정해진 정답에 붙은 두 번째 예측은 FP입니다(VOC · COCO 모두). 그래서 NMS가 남긴 중복 박스는 AP를 깎습니다.

또 IoU 0.5 기준은 VOC의 방식이고, 지금 논문과 YOLO 도구가 대표로 보고하는 값은 COCO의 mAP@[.50:.95]입니다.

원래 · 실습 해설AP는 특정 클래스에 대해 Precision-Recall 곡선(Precision-Recall Curve)의 아래 영역(AUC, Area Under Curve)을 계산한 값입니다.

정정실제 P–R 점을 그대로 이은 곡선의 넓이가 아니라, 보간한 곡선의 넓이입니다. 보간 방식에 따라 같은 예측에서도 값이 달라집니다(실험 3의 세 칸).

  • VOC 2007: 재현율 0, 0.1, …, 1의 11점 평균
  • VOC 2010 이후: 재현율이 바뀌는 모든 점
  • COCO: 재현율 0, 0.01, …, 1의 101점 평균
보충 · 작성 답안 확인

계산 흐름과 COCO 기준이 정확하다

작성 답안의 IoU → TP · FP → 신뢰도 정렬 → P–R 곡선 → 클래스별 AP → 평균 흐름, COCO 10개 IoU 평균, 크기별 AP, "mAP@50 높고 mAP@50:95 낮으면 위치 정밀도 문제"라는 해석은 모두 맞습니다. 다듬을 점은 세 가지입니다.

  • 중복 탐지: "평가 규칙에 따라 FP가 될 수 있다"보다 "VOC · COCO 모두 FP로 처리한다"가 정확합니다.
  • COCO의 용어: COCO는 클래스 평균까지 낸 값을 그냥 AP라고 부릅니다. 그래서 같은 숫자를 논문은 AP, 도구는 mAP로 적기도 합니다.
  • 신뢰도 임계값과 무관: AP는 모든 임계값을 훑은 값이라, 배포 때 고를 conf 값의 성능은 따로 P · R로 확인해야 합니다.
보충 · 실무에서 mAP만 보면 안 되는 이유

평균이 가리는 것

  • 클래스 불균형: 클래스마다 같은 가중치로 평균하므로, 드문 클래스의 AP가 크게 변하면 mAP도 크게 흔들립니다. 반대로 중요한 클래스 하나의 실패가 묻히기도 합니다.
  • 운영 조건: 실제 서비스는 한 conf 임계값에서 돌아가므로 그 지점의 Precision · Recall, 지연 시간, 메모리를 함께 봅니다.
  • 오류 유형: 위치 · 분류 혼동 · 중복 · 배경 · 놓침으로 나눠 보면 무엇을 고칠지 보입니다(YOLO 원 논문의 분석 방식).

mAP는 객체 탐지 모델의 클래스별 AP를 평균한 값입니다.

AP를 구하려면 한 클래스의 예측을 신뢰도 순으로 정렬하고, 정답과의 IoU가 기준 이상이면서 아직 짝이 없는 정답과 만나면 TP, 아니면 FP로 판정합니다. 같은 객체에 붙은 중복 박스도 FP입니다. 예측을 하나씩 추가할 때마다 Precision과 Recall을 계산해 곡선을 그리고, 그 곡선을 오른쪽 최댓값으로 보간한 넓이가 AP입니다. 탐지에서는 배경의 TN을 셀 수 없어서 ROC 대신 P–R 곡선을 씁니다.

중요한 건 평가 조건입니다. VOC는 IoU 0.5 기준이고, COCO는 0.5부터 0.95까지 10개 기준을 평균해 위치 정확도까지 봅니다. 그래서 mAP@50이 높은데 mAP@50:95가 낮으면 객체는 찾지만 박스가 느슨하다는 뜻입니다. 실무에서는 클래스별 · 크기별 AP와 운영 임계값에서의 정밀도 · 재현율, 지연 시간을 함께 보겠습니다.

정정 · 작성 답안에서 바로잡을 부분
원래 · 작성 답안학습 성능 높음 + 실제 성능 낮음 → 평가가 잘못됐는가? 데이터 누수·중복 / 실제 환경이 다른가? … 가장 먼저 과적합으로 단정하지 않고, 데이터 누수와 분포 변화를 확인한 뒤

정정방향은 맞지만 논리 한 단계가 빠졌습니다. 데이터 누수는 학습 점수가 아니라 검증 점수를 부풀리는 문제입니다. 질문에는 "학습 점수 높음, 새 이미지 점수 낮음"만 있으므로, 원인을 가르는 열쇠는 검증 점수입니다.

  • 검증도 낮다면 누수가 아니라 과적합이 1순위입니다. 이때 "과적합으로 단정하지 않는다"는 오히려 진단을 늦춥니다.
  • 검증이 높을 때 비로소 누수 · 분포 변화를 의심하고, 그룹 단위로 다시 나눈 검증으로 둘을 구분합니다(실험 4).
보충 · 불량이 드물고 종류가 다양할 때

정상 이미지만으로 학습하는 이상 탐지

불량 사진이 수십 장뿐이고 새 불량 유형이 계속 생긴다면, 분류보다 정상 제품의 모습만 학습하고 거기서 벗어난 정도를 점수로 쓰는 이상 탐지가 맞을 수 있습니다.

대표적으로 사전 학습 CNN 특징을 정상 이미지에서 모아 두고 가장 가까운 거리로 점수를 매기는 PatchCore(Roth 외, CVPR 2022)가 산업 검사 벤치마크(MVTec AD)에서 널리 쓰입니다. 불량 위치를 지도로 보여 주는 것도 장점입니다.

보충 · 증강을 고르는 기준

현장에서 실제로 생기는 변화만

  • 좋은 증강: 조명 · 노출 변화, 작은 회전 · 이동(지그에 놓이는 오차), 센서 잡음, 약한 흐림
  • 위험한 증강: 불량이 변색이면 색상 변환, 불량이 좌우 비대칭 위치로 정의되면 좌우 반전, 미세 스크래치가 불량이면 강한 흐림 · 축소

증강 뒤 이미지를 사람이 직접 보고 "이 사진의 라벨이 여전히 맞는가"를 확인하는 것이 가장 확실한 검사입니다.

보충 · 작성 답안 확인

대응 목록은 충실하다

작성 답안의 그룹 분할, 실패 사례 분류, 전이학습, 현실적 증강, weight decay · dropout · early stopping, 임계값 점검, 재현율 · PR-AUC 평가, "대표적인 실제 이미지가 없으면 현장 성능을 보장할 수 없다"는 한계 설명은 모두 정확합니다.

여기에 이상 탐지와 지름길 학습 점검(Grad-CAM)을 더하면, 촬영을 더 못 하는 상황에서 쓸 수 있는 수단이 대부분 갖춰집니다.

먼저 학습, 검증, 새 이미지 세 점수를 나란히 보겠습니다. 검증 점수도 낮으면 과적합이고, 검증은 높은데 새 이미지만 낮으면 같은 제품의 연속 사진이 학습과 검증에 섞인 데이터 누수나, 조명 · 카메라가 달라진 분포 변화를 의심합니다.

그래서 제품이나 로트 단위로 그룹 분할을 다시 하고, 새 이미지 오답을 조건별로 묶고, Grad-CAM으로 모델이 불량이 아닌 배경을 보고 있지 않은지 확인하겠습니다.

개선은 촬영 없이 가능한 것부터 하겠습니다. 사전 학습 모델로 전이학습을 하고, 현장에서 실제로 생기는 조명 · 위치 변화만 증강하며, weight decay와 조기 종료를 씁니다. 불량이 드물고 다양하면 정상 이미지만으로 학습하는 이상 탐지도 비교하겠습니다.

평가는 정확도 대신 불량 재현율과 PR-AUC, 운영 임계값의 미탐률로 하고, 대표적인 현장 이미지가 없으면 성능을 보장할 수 없다는 한계도 함께 보고하겠습니다.

면접 · 전문가 답변

희귀 질환 여부를 판별하는 의료 이미지 300장으로 분류 모델을 처음부터 학습시키려 해요. 이 접근에는 어떤 문제가 있을까요? 어떤 대안을 제안할 건가요?

한 줄 요약

무작위 초기화부터 학습하면 수백만~수천만 개의 파라미터를 300장, 그중 질환 사례는 수십 장으로 맞추게 되어 과적합이 거의 확실하다. 더 큰 문제는 평가 자체를 믿기 어렵다는 점이다.

  • 평가 문제: 질환 30명으로 잰 민감도 90%는 95% 신뢰구간이 약 74~97%(폭 20%p 이상)이고, 정확도는 "모두 정상"만으로도 높게 나온다
  • 누수 문제: 한 환자의 여러 이미지가 학습 · 테스트에 나뉘면 성능이 부풀려진다

대안은 사전 학습 모델(가능하면 의료 영상) + 단순한 분류기, 환자 단위 계층 교차검증, 민감도 · 특이도 · PR-AUC와 신뢰구간 보고, 그리고 외부 기관 검증이다.

환자 단위 계층 교차검증 + 불균형에 맞는 지표 + 신뢰구간
import numpy as np
from sklearn.model_selection import StratifiedGroupKFold
from sklearn.metrics import roc_auc_score, average_precision_score, confusion_matrix
from statsmodels.stats.proportion import proportion_confint

cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)
oof = np.zeros(len(y))
for tr, va in cv.split(X, y, groups=patient_id):      # 한 환자의 이미지는 한 폴드에만
    clf = fit_on_pretrained_features(X[tr], y[tr])     # 사전 학습 특징 + 단순 분류기
    oof[va] = clf.predict_proba(X[va])[:, 1]

print("AUROC", roc_auc_score(y, oof), "PR-AUC", average_precision_score(y, oof))
tn, fp, fn, tp = confusion_matrix(y, oof >= thr).ravel()  # thr는 학습 폴드 안에서 정한 값
print("민감도", proportion_confint(tp, tp + fn, alpha=0.05, method="wilson"))
print("특이도", proportion_confint(tn, tn + fp, alpha=0.05, method="wilson"))

정정 · 작성 답안에서 바로잡을 부분
원래 · 작성 답안Precision·PPV — 양성 예측의 신뢰도 확인

정정PPV는 모델만의 성질이 아니라 유병률에 따라 달라지는 값이라, 데이터셋에서 잰 값을 그대로 현장 성능으로 말하면 안 됩니다.

희귀 질환 데이터는 보통 질환 사례를 일부러 모아 유병률이 현장보다 훨씬 높습니다. 민감도 90% · 특이도 95%인 모델도 다음처럼 달라집니다.

  • 데이터 유병률 10%에서 PPV ≈ 67%
  • 현장 유병률 1%에서 PPV ≈ 15% ("질환" 판정 100건 중 약 85건이 오경보)

그래서 데이터에서는 민감도 · 특이도처럼 유병률과 무관한 값을 보고하고, PPV · NPV는 현장 유병률로 다시 계산해 함께 제시합니다(실험 5).

원래 · 작성 답안환자 단위로 계층화된 교차검증을 사용하되, 모델 선택에 사용한 데이터와 최종 테스트 데이터는 구분해야 합니다.

정정원칙은 맞지만, 300장에서 최종 테스트를 따로 떼면 테스트 양성이 6~10명 수준으로 줄어 그 숫자를 믿을 수 없습니다. 이 규모에서는 보통 다음 방식을 씁니다.

  • 중첩 교차검증(nested CV): 바깥 폴드는 평가만, 안쪽 폴드에서 하이퍼파라미터 · 임계값을 고른다
  • 모든 데이터를 한 번씩 평가에 쓰되, 결과에 신뢰구간을 붙인다
  • 진짜 일반화 근거는 다른 병원 · 다른 장비의 외부 검증으로 따로 확보한다
보충 · 어떤 사전 학습 모델을 쓸까

ImageNet, 의료 영상 사전 학습, 파운데이션 모델

  • ImageNet: 자연 사진으로 배웠지만 경계 · 질감 같은 저수준 특징은 의료 영상에도 통합니다. 데이터가 적을수록 효과가 큽니다(Raghu 외, NeurIPS 2019는 큰 데이터에서는 이득이 줄어든다고 보고).
  • 의료 영상 사전 학습: CT · MRI · 초음파로 학습한 RadImageNet(Mei 외, 2022) 같은 모델은 같은 영상 종류일수록 유리합니다.
  • 파운데이션 모델 임베딩: 대규모 의료 영상으로 자기지도 학습한 인코더의 특징을 뽑고 선형 분류기만 학습하는 방식이 수백 장 규모에서 강한 기준선입니다.
보충 · 라벨과 보고

300장에서는 라벨 한 장의 무게가 크다

  • 라벨 품질: 판독자 2명 이상과 불일치 조정 절차, 가능하면 조직검사 같은 확정 진단을 기준으로 삼습니다. 양성 한 명의 라벨 오류가 민감도를 3%p 이상 바꿉니다(양성 30명 기준).
  • 보정(calibration): 의사가 확률을 위험도로 해석하므로, 예측 확률이 실제 비율과 맞는지 신뢰도 그림으로 확인합니다.
  • 보고 지침: 예측 모델 논문은 TRIPOD+AI(2024) 같은 지침에 맞춰 데이터 출처, 분할 방식, 결측, 한계를 밝힙니다.
보충 · 작성 답안 확인

문제 진단과 대안은 정확하다

작성 답안의 "300장보다 300명이 중요하다", 환자 단위 분할, 교란 요인, 특징 추출부 고정 후 제한적 미세 조정, 단순 모델 비교, 클래스 가중치 · 신중한 증강 · 임계값 조정, 민감도 · 특이도 · PR-AUC · AUROC · calibration · 신뢰구간 · 외부 검증은 모두 맞습니다. 위의 두 정정(PPV의 유병률 의존성, 소규모에서의 테스트 분리 방식)만 보완하면 됩니다.

300장으로 처음부터 학습하면 수백만~수천만 개의 파라미터를 수십 장의 질환 사례로 맞추게 돼 과적합이 거의 확실하고, 경계나 질감 같은 기본 특징도 제대로 배우지 못합니다. 또 질환이 드물어서 모두 정상이라고만 해도 정확도가 높게 나오고, 한 환자의 이미지가 학습과 테스트에 나뉘면 누수로 성능이 부풀려집니다.

더 큰 문제는 평가의 불확실성입니다. 테스트 양성이 30명이면, 민감도를 90%로 쟀어도 95% 신뢰구간이 대략 74~97%까지 벌어져서 숫자 하나로 모델을 고르기 어렵습니다.

그래서 의료 영상으로 사전 학습된 모델의 특징에 단순한 분류기를 붙이고, 필요할 때만 상위 층을 낮은 학습률로 미세 조정하겠습니다. 평가는 환자 단위 계층 교차검증으로 하고, 민감도 · 특이도 · PR-AUC와 신뢰구간, calibration을 보고하겠습니다. PPV는 현장 유병률로 다시 계산하고, 마지막으로 다른 병원 데이터로 외부 검증을 하기 전에는 임상 배포 근거로 충분하지 않다고 명확히 말하겠습니다.

Q1 YOLO (실습 해설)오류한 번의 순전파로 위치와 클래스를 함께 예측, 실시간 응용, 작은 객체에 약함"R-CNN보다 빠르면서 정확도도 높다"는 틀림(원 논문은 mAP 약 10%p 낮음). v3~v5는 최신이 아니고, 주류는 앵커 프리 · NMS 제거. 셀은 중심 가능성만이 아니라 박스 · 신뢰도 · 클래스 확률을 함께 예측. NMS 후처리가 남아 있었음
Q1 작성 답안정확"한 번 본다"의 정확한 의미, 그리드 설명의 한계, 단일 계보가 아님, 속도 단정 금지, 작은 객체 · 밀집 · 도메인 변화 한계원 논문 수치(63.4 vs 73.2 mAP), 현대 YOLO의 다중 스케일 격자 · 동적 배정 · 앵커 프리, NMS 없는 최신 모델 추가
Q2 mAP (실습 해설)보완클래스별 AP의 평균, IoU로 TP 판정, P–R 곡선 요약신뢰도 정렬과 "정답당 TP 하나"(중복은 FP) 누락. AP는 보간한 곡선의 넓이. 0.5는 VOC 기준이고 COCO는 0.50~0.95 평균
Q2 작성 답안정확계산 흐름, COCO 10개 IoU 평균, 크기별 AP, mAP@50과 mAP@50:95의 해석, 보고 시 조건 명시중복 탐지는 VOC · COCO 모두 FP, COCO는 클래스 평균값을 AP라고 부름, AP는 conf 임계값과 무관한 요약
면접 1 새 이미지 성능 저하 (작성 답안)보완그룹 분할, 실패 사례 분류, 전이학습, 현실적 증강, 규제, 재현율 · PR-AUC, 현장 성능 보장의 한계누수는 검증 점수를 부풀리는 문제이므로 학습 · 검증 · 새 이미지 세 점수로 먼저 원인을 갈라야 함. 이상 탐지, Grad-CAM 지름길 점검 추가
면접 2 의료 이미지 300장 (작성 답안)보완"300장보다 300명", 환자 단위 분할, 교란 요인, 전이학습, 불균형 대응, 민감도 · 특이도 · calibration · 신뢰구간 · 외부 검증PPV는 유병률에 따라 바뀌므로 현장 유병률로 다시 계산. 300장에서는 중첩 교차검증 + 신뢰구간 + 외부 검증이 현실적
