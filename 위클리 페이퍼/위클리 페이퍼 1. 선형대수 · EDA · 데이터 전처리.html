선형대수학이란 어떤 학문이며, 왜 머신러닝/딥러닝에 필요한가요?

한 줄 요약 선형대수학은 데이터를 숫자 묶음(벡터·행렬)으로 표현하고, 그 묶음을 한꺼번에 변환·계산하는 언어이며, 머신러닝은 처음부터 끝까지 이 언어로 쓰여 있다.

자주 하는 오해 · "기울기 계산은 선형대수로 한다"

기울기(gradient)를 구하는 것은 미적분(편미분, 연쇄 법칙)이다. 선형대수는 그 기울기를 벡터·행렬로 묶어서 표현하고 한꺼번에 계산하게 해 준다. 역전파는 "연쇄 법칙(미적분)을 행렬 곱(선형대수)으로 층마다 거꾸로 전달하는 과정"이라고 말하는 것이 정확하다.

선형대수학은 벡터와 행렬, 그리고 그 사이의 선형 변환을 다루는 학문입니다. 머신러닝에서는 데이터 한 건을 벡터로, 데이터셋을 행렬로 표현하기 때문에 대부분의 계산이 선형대수로 이뤄집니다. 신경망의 한 층은 가중치 행렬과 입력 벡터의 곱에 활성화 함수를 씌운 것이고, 추천·검색의 유사도는 내적으로, PCA 같은 차원 축소는 공분산 행렬의 고유값 분해로 계산합니다. 학습 시 기울기는 미분으로 구하지만, 수많은 파라미터의 기울기를 행렬 연산으로 묶어 GPU에서 병렬 처리하기 때문에 딥러닝이 현실적인 속도로 돌아갈 수 있습니다.

심화 · 배경

누가 만든 개념인가

통계학자 존 튜키(John Tukey)가 1977년 저서 Exploratory Data Analysis로 정리. 가설을 먼저 세우고 검증하는 확증적 분석(CDA)과 달리, 데이터를 먼저 보고 가설을 만들어 내는 단계다.

심화 · 주의

요약 통계만 믿지 말 것

위 실험 3처럼 평균·분산·상관계수가 같아도 그래프 모양은 완전히 다를 수 있다. 그래서 수치와 시각화를 함께 본다.

심화 · 결과물

EDA가 끝나면 남는 것

① 전처리 할 일 목록 ② 파생 변수 아이디어 ③ 사용할 모델·평가지표 방향. 이게 없으면 그래프만 그리고 끝난 것이다.

EDA는 모델링 전에 데이터의 구조와 특성을 파악하는 탐색 단계입니다. 먼저 크기와 자료형을 보고, 결측값·중복·이상치 같은 품질 문제를 확인한 뒤, 변수 하나씩의 분포와 변수 간 관계를 요약 통계와 히스토그램·박스플롯·산점도·상관 히트맵으로 살펴봅니다. 앤스컴 콰르텟처럼 요약 통계가 같아도 분포가 전혀 다를 수 있어 시각화를 꼭 함께 봅니다. 최종적으로는 어떤 전처리가 필요한지, 어떤 파생 변수를 만들지, 어떤 모델과 지표를 쓸지 방향을 정하는 것이 EDA의 목적입니다.

① 결측값 처리

심화 · 결측의 3가지 유형
  • MCAR 완전 무작위: 예시) 설문지가 우연히 젖어서 지워짐 → 삭제해도 편향 적음
  • MAR 다른 관측 변수와 관련: 예시) 고령층이 소득 칸을 더 자주 비움 → 다른 변수로 예측 대체
  • MNAR 그 값 자체와 관련: 예시) 소득이 높은 사람일수록 소득을 안 적음 → 삭제·평균 대체 모두 왜곡, "결측 여부" 자체가 정보
처리 방법 선택 기준 (일반적 가이드)
  • 결측이 아주 적고 무작위 → 행 삭제
  • 한 컬럼이 대부분 비었다 → 열 삭제 검토 (몇 % 이상이면 지운다는 정해진 규칙은 없음, 그 컬럼의 중요도와 함께 판단)
  • 숫자, 분포가 대칭 → 평균 대체
  • 숫자, 치우쳤거나 이상치 있음 → 중앙값 대체
  • 범주형 → 최빈값 또는 'Unknown'
  • 시계열 → 앞/뒤 값 (ffill, 보간)
  • 변수 간 관계가 강함 → KNN · 회귀 예측 대체
실험 4 결측 대체 방법 비교 예시 데이터 · 가상의 월 소득 200명 (만원, 50 단위 기록)
결측이 생기기 전의 전체 데이터(정답)를 알고 있는 예시라서, 각 대체 방법이 분포를 얼마나 바꾸는지 정답과 비교할 수 있습니다. 주황 막대 = 채워 넣은 값.
관측된 값 대체한 값 이 데이터의 평균 정답 평균

자주 하는 오해 · dropna(thresh=3)의 의미

"결측값이 3개 미만인 행만 남긴다"로 이해하기 쉽지만 틀렸다. thresh=3은 결측이 아닌 값이 3개 이상인 행만 남긴다는 뜻이다. 결측 개수가 아니라 채워진 값의 개수를 센다.

예시 코드
# 결측 확인 → 처리
df.isna().mean().sort_values(ascending=False)   # 컬럼별 결측 비율
df['income_missing'] = df['income'].isna().astype(int)  # 결측 여부를 정보로 남기기
df['income'] = df['income'].fillna(df['income'].median())
df['region'] = df['region'].fillna('Unknown')

② 중복값 처리

심화 · 두 종류의 중복
  • 완전 중복: 모든 컬럼이 같은 행. 수집·병합 과정에서 두 번 들어간 경우가 많다 → 하나만 남기고 삭제
  • 키 중복: 같은 고객ID·주문번호인데 다른 값이 있는 행 → 최신 값 하나만 남길지, 합칠지 판단 필요
심화 · 지우면 안 되는 중복

예시) 같은 날 같은 상품을 두 번 산 기록은 값이 같아도 실제로 두 번 일어난 일이다. 고유 ID나 타임스탬프가 없으면 진짜 중복인지 구분할 수 없으므로, 삭제 전에 데이터가 어떻게 수집됐는지 확인한다.

예시 코드
df.duplicated().sum()                                        # 완전 중복 개수

③ 이상치 처리

심화 · 탐지 방법
  • 시각화: 박스플롯, 산점도, 히스토그램
  • IQR: [Q1 − 1.5·IQR, Q3 + 1.5·IQR] 밖. 사분위수 기반이라 이상치 자체에 덜 휘둘림
  • Z-score: |z| > 3 (기준 3은 관례). 정규분포에 가까울 때 적합. 평균·표준편차가 이상치에 끌려가는 한계 → 아래 실험에서 확인
  • 모델 기반: Isolation Forest, LOF. 여러 변수를 동시에 볼 때
심화 · 처리 방법
  • 삭제: 명백한 입력 오류 (예시: 나이 250세, 음수 가격)
  • 클리핑(윈저화): 경계값으로 잘라냄. 데이터 수 유지
  • 로그 변환: 소득·가격처럼 오른쪽 꼬리가 긴 분포
  • 강건한 방법: RobustScaler, 트리 기반 모델은 이상치 영향이 적음
  • 유지: 사기 탐지·장비 고장 예측에서는 이상치가 곧 찾아야 할 대상

계산 방식: 사분위수는 pandas 기본값과 같은 선형 보간, σ는 모집단 표준편차(ddof=0, scipy.stats.zscore 기본값).

예시 코드
q1, q3 = df['purchase'].quantile([0.25, 0.75])
iqr = q3 - q1
low, high = q1 - 1.5 * iqr, q3 + 1.5 * iqr

outliers = df[(df['purchase'] < low) | (df['purchase'] > high)]   # 먼저 눈으로 확인
df['purchase_clip'] = df['purchase'].clip(low, high)               # 클리핑
df['purchase_log']  = np.log1p(df['purchase'])                     # 로그 변환
심화 · 실무에서 자주 놓치는 두 가지

1. 처리 순서: 흔히 쓰는 순서는 중복 제거 → 이상치 확인 → 결측 대체다. 이상치가 남은 상태에서 평균으로 결측을 채우면 대체값이 왜곡되기 때문이다. 다만 정해진 규칙은 아니고, 데이터와 목적에 따라 바뀔 수 있다 (예: 중앙값으로 대체한다면 이상치의 영향이 작다).

2. 데이터 누수(leakage): 대체에 쓰는 평균·중앙값, 이상치 경계는 학습 데이터에서만 계산하고 테스트 데이터에는 그 값을 그대로 적용한다. 전체 데이터로 계산하면 테스트 정보가 학습에 새어 들어가 성능이 실제보다 좋게 나온다. scikit-learn Pipeline을 쓰면 이 순서를 지키기 쉽다.

세 가지 모두 탐지한 뒤 원인을 판단하고 처리합니다. 결측값은 isna()로 확인하고, 양이 적고 무작위면 삭제하고, 숫자형은 평균이나 분포가 치우쳤으면 중앙값, 범주형은 최빈값으로 대체하며, 결측 자체가 의미 있으면 결측 여부 컬럼을 따로 만듭니다. 다만 평균 대체는 분산을 줄이므로 결측이 많으면 예측 기반 대체를 고려합니다. 중복값은 duplicated()로 찾아 제거하되, 실제로 반복된 거래처럼 정상적인 중복인지 먼저 확인합니다. 이상치는 박스플롯과 IQR·Z-score로 찾고, 입력 오류면 삭제, 진짜 극단값이면 클리핑이나 로그 변환을 쓰며, 사기 탐지처럼 이상치가 목적이면 유지합니다. 그리고 대체값과 경계는 학습 데이터에서만 계산해 데이터 누수를 막습니다.
