Q1
실습 해설

이미지를 모델에 입력하기 전에 리사이징(Resizing)과 정규화(Normalization)를 하는 이유는 무엇인가요?

한 줄 요약

리사이징은 크기가 제각각인 이미지를 같은 H×W로 맞춰 하나의 배치 텐서(N×C×H×W)로 쌓고, 사전 학습 모델이 학습한 해상도와 물체 크기에 맞추는 작업이다. 정규화는 0~255 픽셀을 0~1로 바꾼 뒤 채널별 (x − 평균) / 표준편차로 입력을 0 근처에 모으는 작업이다.

  • 리사이징에서 조심할 것: 종횡비 왜곡, 가장자리 물체 잘림, 물체가 너무 작아지는 것
  • 정규화가 주는 것: 손실 곡면의 조건수가 좋아져 큰 학습률로 빨리 수렴하고, 사전 학습 모델과 같은 입력 분포를 맞춘다

입력 정규화는 경사 소실의 해결책이 아니라 최적화 조건 개선이다. 사전 학습 모델에는 학습 당시와 똑같은 전처리를 써야 한다.

핵심 전처리는 직접 쓰기보다 가중치에서 가져온다

직접 쓰기 · 작성 답안의 코드
from PIL import Image
import torch
from torchvision import transforms

preprocess = transforms.Compose([
    transforms.Resize(256),         # 짧은 변 256, 비율 유지
    transforms.CenterCrop(224),
    transforms.ToTensor(),          # 0~255 → 0~1, C×H×W
    transforms.Normalize(mean=(0.485, 0.456, 0.406),
                         std=(0.229, 0.224, 0.225)),
])

def preprocess_image(image: Image.Image) -> torch.Tensor:
    return preprocess(image).unsqueeze(0)   # 1×C×H×W
가중치에 딸린 전처리 · 학습 당시 설정을 그대로 쓴다
from PIL import Image
import torch
from torchvision import models

weights = models.ResNet18_Weights.DEFAULT
preprocess = weights.transforms()   # resize 256, crop 224, mean·std
print(preprocess)                   # 설정을 눈으로 확인

image = Image.open("cat.jpg").convert("RGB")   # 3채널 보장
x = preprocess(image).unsqueeze(0)  # 1×3×224×224
model = models.resnet18(weights=weights).eval()
with torch.inference_mode():
    probs = model(x).softmax(dim=1)
2 · 핵심 정리와 보충
정정 · 실습 해설에서 바로잡을 부분
원래 · 실습 해설딥러닝 모델은 고정된 크기의 입력을 받도록 설계되므로, 다양한 크기의 이미지를 일관된 형태로 맞춰야 합니다.

정정모든 모델이 고정 크기만 받는 것은 아닙니다. torchvision의 ResNet은 마지막에 AdaptiveAvgPool2d가 있어 크기가 다른 이미지도 그대로 처리합니다. 크기를 맞추는 실제 이유는 다음 세 가지입니다.

  • 배치: 한 배치의 이미지는 같은 H×W여야 하나의 텐서로 쌓인다
  • 구조: Flatten 뒤 완전연결 층이 있는 모델(VGG식), 위치 임베딩 개수가 정해진 ViT는 입력 크기가 고정된다(다른 크기는 위치 임베딩을 보간해야 한다)
  • 사전 학습 조건: 224로 학습한 모델은 물체가 그 정도 크기로 보일 때 가장 잘 맞힌다
원래 · 실습 해설이렇게 하면 모델이 더 안정적으로 학습할 수 있으며, 특히 경사 소실(vanishing gradient) 문제를 완화하는 데 도움이 됩니다.

정정입력 정규화는 첫 층에 들어가는 값의 크기와 중심만 맞춥니다. 깊은 층을 거치며 기울기가 지수적으로 작아지는 경사 소실은 활성화 함수 · 초기화 · 잔차 연결 · 정규화 층으로 해결합니다(위클리 05 면접 1).

입력 정규화의 실제 효과는 최적화 조건 개선입니다. 모든 입력이 양수이고 평균이 크면 손실 곡면이 한 방향으로 길쭉해져(조건수 증가) 학습률을 작게 잡아야 하고 수렴이 느립니다(실험 2). 시그모이드 · tanh 첫 층이 0~255 입력으로 포화되는 것을 막는 간접 효과는 있지만, 그것을 경사 소실 해결이라고 부르면 과장입니다.

보충 · 가장 흔한 조용한 버그

학습과 추론의 전처리가 다르다

전처리가 달라도 오류는 나지 않고 정확도만 떨어집니다. 그래서 찾기 어렵습니다. 자주 나오는 경우는 다음과 같습니다.

  • 색 순서: OpenCV cv2.imread는 BGR로 읽는다. cv2.cvtColor(img, cv2.COLOR_BGR2RGB)로 바꾼다
  • 값 범위: 학습은 0~1 뒤 Normalize, 서비스는 0~255 그대로
  • 통계와 보간법: 다른 mean · std, 다른 리사이즈 보간법

사전 학습 모델은 weights.transforms()로 전처리를 가져오고, 서비스 코드에서도 같은 함수를 재사용합니다.

보충 · 평균과 표준편차는 어디서

훈련 데이터로만 계산한다

사전 학습 모델을 쓰면 그 모델의 통계(ImageNet)를 그대로 씁니다. 처음부터 학습하면서 의료 · 위성 · 현미경처럼 자연 사진과 다른 데이터를 쓸 때는 훈련 세트에서만 채널별 평균 · 표준편차를 계산합니다. 검증 · 테스트 세트까지 넣어 계산하면 정보 누수입니다.

보충 · torchvision v2

ToTensor 대신 ToImage + ToDtype

torchvision.transforms.v2에서는 ToTensor가 지원 중단(deprecated) 예정이고 v2.ToImage() + v2.ToDtype(torch.float32, scale=True)가 권장됩니다. 이 조합이 0~255 → 0~1 변환을 합니다. v2는 이미지와 함께 바운딩 박스 · 마스크도 같은 변환으로 옮겨 주어, 탐지 · 분할에서 좌표를 따로 고칠 필요가 없습니다.

리사이징은 크기가 제각각인 이미지를 같은 높이와 너비로 맞춰 하나의 배치 텐서로 쌓기 위해 합니다. 사전 학습 모델을 쓸 때는 그 모델이 학습한 해상도, 예를 들어 짧은 변 256으로 줄이고 가운데 224를 자르는 조건에 맞춰야 성능이 납니다. 이때 그냥 224×224로 늘이면 종횡비가 왜곡되므로 비율을 유지하고 자르거나 패딩합니다.

정규화는 0~255 픽셀을 0~1로 바꾼 뒤 채널별 평균을 빼고 표준편차로 나눠 입력을 0 근처에 모읍니다. 입력이 모두 큰 양수이면 손실 곡면이 한쪽으로 길쭉해져 학습률을 작게 잡아야 하는데, 정규화하면 조건수가 좋아져 더 빨리, 안정적으로 수렴합니다.

사전 학습 모델에는 학습 당시와 같은 평균, 표준편차, 리사이즈 규칙을 써야 하고, 저는 weights.transforms로 가져와 학습과 서비스에 똑같이 쓰겠습니다. 참고로 입력 정규화는 최적화를 돕는 것이지 깊은 층의 경사 소실을 해결하는 방법은 아닙니다.

데이터 증강(Data Augmentation)이란 무엇이며, 이미지 데이터에서 주로 사용하는 증강 기법에는 어떤 것들이 있나요?

한 줄 요약

데이터 증강은 학습할 때마다 라벨이 바뀌지 않는 무작위 변환을 걸어, 모델이 "이 정도 변화는 같은 것"이라는 불변성을 배우게 하는 규제 기법이다. 핵심은 개수를 늘리는 것이 아니라 훈련 데이터와 실제 환경의 차이를 메우는 것이다.

  • 기하 변환: 뒤집기, 무작위 자르기·크기 조절, 회전·이동
  • 색·화질: 밝기·대비·채도, 블러, 노이즈
  • 가림·혼합: Random Erasing, MixUp, CutMix
  • 자동 정책: AutoAugment, RandAugment, TrivialAugment

고르는 기준은 두 가지다. 라벨을 보존하는가, 실제 환경에서 일어나는 변화인가.

한 줄 요약

전이 학습은 대규모 데이터(예: ImageNet-1k, 약 128만 장 · 1,000클래스)로 학습한 모델의 표현, 즉 특징 추출기를 새 과제에 재사용하는 방법이다. 이미지 분류에서는 두 가지로 쓴다.

  • 특징 추출: 백본을 동결하고 새 분류 헤드만 학습한다. 데이터가 적고 도메인이 비슷할 때

얼마나 풀지는 데이터 양 × 도메인 유사도로 정하고, 사전 학습 때의 전처리도 함께 가져온다. 도메인이 많이 다르면 오히려 손해를 볼 수도 있다(부정적 전이).

정정 · 실습 해설에서 바로잡을 부분
원래 · 실습 해설특정 층(예: 상위 몇 개 층)은 고정하고, 나머지 층들은 새로운 데이터에 맞춰 학습할 수 있도록 설정하여

정정방향이 반대입니다. 상위 층(출력 쪽)은 원래 과제에 특화된 특징을 담고 있어 새 과제에 맞춰 풀어야 하는 층입니다. 고정하는 쪽은 엣지 · 색 · 질감처럼 범용적인 하위 층(입력 쪽)입니다(Yosinski 외, 2014).

순서는 헤드 학습 → 출력 쪽 블록부터 점진적으로 해제이고, 풀어 준 층에는 헤드보다 작은 학습률을 줍니다. 작성 답안은 이 점을 이미 바르게 지적했습니다.

원래 · 실습 해설사전 학습된 모델의 합성곱 층(Convolutional Layers)은 일반적인 이미지 특징(엣지, 패턴, 질감 등)을 잘 학습하고 있기 때문에, 이 부분을 그대로 사용하고

정정합성곱 층 전체가 범용적인 것은 아닙니다. 범용성은 앞쪽 층에서 크고, 뒤쪽 층으로 갈수록 ImageNet 클래스(개 품종, 자동차 부품 등)에 특화됩니다.

그래서 도메인이 비슷하면 합성곱 층 전체를 그대로 써도 되지만, 도메인이 다르면 특징 추출만으로는 성능이 낮고 뒤쪽 블록을 미세 조정해야 합니다(실험 4에서 도메인 차이 1).

전이 학습은 ImageNet 같은 대규모 데이터로 학습한 모델의 특징 추출 능력을 새 과제에 재사용하는 방법입니다. 적은 데이터와 짧은 학습으로도 높은 성능을 얻을 수 있습니다.

이미지 분류에서는 마지막 분류 층을 새 클래스 수에 맞게 바꾸고, 데이터가 적으면 백본을 얼린 채 헤드만 학습하는 특징 추출부터 합니다. 성능이 부족하면 출력 쪽 블록부터 풀어 헤드보다 작은 학습률로 미세 조정합니다. 입력 쪽 층은 엣지나 질감 같은 범용 특징이라 오래 얼려 둡니다.

이때 사전 학습과 같은 전처리를 쓰고, 새로 푼 층을 옵티마이저에 넣었는지, 배치 정규화 통계가 바뀌는지 확인하겠습니다. 도메인이 많이 다르면 특징 추출만으로는 부족하거나 손해일 수 있어서, 처음부터 학습한 모델과 검증 성능으로 비교하겠습니다.

import torch
from torch import nn
from torch.nn.utils.rnn import pack_padded_sequence

class SentimentLSTM(nn.Module):
    def __init__(self, vocab_size, emb=128, hidden=128):
        super().__init__()
        self.emb = nn.Embedding(vocab_size, emb, padding_idx=0)
        self.lstm = nn.LSTM(emb, hidden, batch_first=True, bidirectional=True)
        self.fc = nn.Linear(2 * hidden, 1)
        with torch.no_grad():                            # 게이트 순서: i, f, g, o
            for name, p in self.lstm.named_parameters():
                if name.startswith("bias_ih"):
                    p[hidden:2 * hidden].fill_(1.0)      # 망각 게이트 편향 1

    def forward(self, tokens, lengths):                  # 뒤쪽 패딩 배치
        packed = pack_padded_sequence(self.emb(tokens), lengths.cpu(),
                                      batch_first=True, enforce_sorted=False)
        _, (h_n, _) = self.lstm(packed)                  # 실제 길이 위치의 마지막 상태
        h = torch.cat([h_n[-2], h_n[-1]], dim=1)         # 정방향 끝 + 역방향 끝(문장 맨 앞)
        return self.fc(h).squeeze(1)                     # BCEWithLogitsLoss와 함께

지금이라면 사전 학습 Transformer

감성 분류 같은 문장 분류는 BERT 계열 사전 학습 모델을 미세 조정하는 것이 일반적인 기준선입니다. 최대 입력 길이(예: 512토큰)를 넘는 리뷰는 앞 · 뒤를 함께 남기거나 구간으로 나눠 예측을 합칩니다. LSTM은 자원이 매우 제한된 환경이나 순차 처리가 필요한 경우의 선택지입니다.

먼저 기본 RNN의 장기 의존성 문제를 의심하겠습니다. 역전파는 시점마다 순환 가중치와 tanh 미분으로 된 야코비안을 곱하는데, 이 행렬의 최대 특이값이 1보다 작으면 앞 단어까지 가는 기울기가 거리에 따라 지수적으로 사라집니다. 순전파에서도 고정 크기 은닉 상태를 계속 덮어써 앞 정보가 희석됩니다.

다만 모델 탓으로 단정하기 전에 전처리를 확인하겠습니다. 길이를 자를 때 앞부분이 잘렸는지, 패딩 위치의 출력을 읽고 있지는 않은지 봅니다. 그다음 위치별 기울기 노름과, 앞 단어를 가리거나 위치를 옮겼을 때의 예측 변화로 원인을 확인합니다.

해결은 셀 상태를 더하기로 전달하는 LSTM이나 GRU로 바꾸고 망각 게이트 편향을 1로 둡니다. 양방향으로 맨 앞 단어를 역방향이 마지막에 읽게 하고, 모든 시점을 쓰는 어텐션 풀링을 더하겠습니다. 문장이 매우 길면 사전 학습 Transformer를 쓰고, 기울기 클리핑은 폭주가 보일 때 함께 쓰겠습니다.

def train_step(model, x, optimizer, noise_std=0.2):
    noisy = x + noise_std * torch.randn_like(x)        # 입력만 손상
    loss = nn.functional.mse_loss(model(noisy), x)    # 정답은 깨끗한 원본
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()
    return loss.item()

@torch.no_grad()
def copy_test(model, x_val, train_mean):
    model.eval()
    mse = nn.functional.mse_loss
    noise = train_mean + 0.2 * torch.randn_like(x_val)    # 평균 이미지 + 의미 없는 잡음
    val_err = mse(model(x_val), x_val).item()
    baseline = mse(train_mean.expand_as(noise), noise)    # 잡음을 전부 지웠을 때의 오차
    pass_rate = 1 - mse(model(noise), noise) / baseline   # 잡음이 출력에 남은 비율
    return val_err, pass_rate.item()                  # pass_rate ≈ 1이면 복사기
2 · 핵심 정리와 보충
정정 · 작성 답안에서 바로잡을 부분
원래 · 작성 답안의심해야 할 원인 … 훈련 데이터를 암기했을 가능성이 있습니다.

정정암기와 복사는 증상이 다릅니다. 둘을 같은 원인 목록에 두면 진단이 흐려집니다.

  • 암기(과적합): 훈련 이미지는 잘 복원하지만 검증 이미지는 못 한다
  • 복사(항등 함수): 훈련 · 검증은 물론 무작위 잡음까지 잘 복원한다

질문의 "그대로 복사하는 것처럼 동작"은 복사입니다. 검증 오차와 잡음 통과율을 함께 보면 둘을 구분할 수 있습니다(실험 6).

보충 · 작은 병목도 만능이 아니다

강력한 디코더는 1차원으로도 외운다

이론적으로 인코더 · 디코더가 충분히 강력하면, 잠재 차원이 1이어도 각 훈련 샘플에 번호를 매겨 그대로 외울 수 있습니다(Goodfellow 외, 『Deep Learning』 14장). 그래서 병목 축소만으로 끝내지 말고 검증 오차와 규제를 함께 써야 합니다.

보충 · 압축률은 차원 수가 아니다

파일 크기는 비트 수로 잰다

잠재 벡터 k개를 float32로 저장하면 4k바이트입니다. 64×64 RGB 원본(12,288바이트)을 k = 3,072로 줄여도 float32면 12,288바이트로 같아서 압축이 전혀 아닙니다.

실제 학습 기반 압축은 잠재값을 양자화하고 엔트로피 부호화한 뒤, bpp(픽셀당 비트)와 PSNR · SSIM · MS-SSIM을 함께 그린 rate–distortion 곡선으로 JPEG · WebP 같은 기존 코덱과 비교합니다.

보충 · "유의미한 특징"을 재는 법

복원 오차 말고 다른 지표

  • 선형 프로브: 잠재 벡터 위에 로지스틱 회귀를 학습해, 라벨이 있는 소량의 데이터에서 분류 성능을 본다
  • 잠재 보간: 두 이미지의 잠재 벡터 사이를 이었을 때 중간 복원이 자연스러운지 본다
  • 잡음 강건성: 입력에 잡음을 넣어도 잠재 벡터가 크게 바뀌지 않는지 본다

복원 오차가 거의 0인데 쓸모 있는 특징이 없다면, 오토인코더가 항등 함수, 즉 복사를 배운 것입니다. 복원 손실만 줄이면 복사가 가장 쉬운 해답이라, 정보를 줄이도록 강제하는 장치가 없으면 이렇게 됩니다.

원인은 두 가지를 먼저 보겠습니다. 잠재 차원이 입력에 가까울 만큼 크거나, U-Net처럼 스킵 연결이 병목을 우회하는 경우입니다. 확인은 의미 없는 무작위 잡음 이미지를 넣어 보는 것입니다. 잡음까지 그대로 복원하면 복사기이고, 검증 이미지만 못 하면 복사가 아니라 암기입니다.

해결은 병목을 줄이고 스킵 연결을 없앤 뒤, 입력에 잡음을 넣고 원본을 맞히는 잡음 제거 오토인코더나 희소성, VAE 같은 규제를 넣겠습니다. 압축이 목적이면 잠재값을 양자화하고 엔트로피 부호화해서 픽셀당 비트 수와 PSNR, SSIM을 함께 보는 rate–distortion으로 평가하겠습니다.
