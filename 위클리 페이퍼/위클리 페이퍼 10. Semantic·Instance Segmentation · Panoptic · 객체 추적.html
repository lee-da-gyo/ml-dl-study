Q1
면접형 질문 · 작성 답안 검토

자율주행 차량이 카메라로 도로 이미지를 분석해요. '이 픽셀들이 차인지 도로인지 사람인지' 구분하는 것과, '왼쪽 차와 오른쪽 차를 서로 다른 개체로 구별'하는 것은 다른 문제예요. 이 둘을 각각 어떤 방식으로 해결할 건가요?

한 줄 요약

두 문제는 답의 단위가 다르다.

  • "이 픽셀은 무엇인가" → Semantic Segmentation: 모든 픽셀에 클래스를 하나씩 붙인다. 차 두 대는 둘 다 '차'로 칠해질 뿐, 몇 대인지는 구분하지 않는다.
  • "이 픽셀은 어느 개체인가" → Instance Segmentation: 차·사람처럼 셀 수 있는 물체(things)마다 마스크 한 장과 클래스·신뢰도를 낸다. 도로·하늘 같은 배경(stuff)은 출력하지 않는다.

둘을 한 번에 얻으려면 모든 픽셀에 (클래스, 개체 ID)를 하나씩 주는 Panoptic Segmentation을 쓴다. 영상에서는 객체 추적이 프레임이 바뀌어도 같은 차에 같은 ID를 이어 붙인다.

가까운 차선의 트럭 A가 먼 차선의 승용차 B를 추월하면서 화면에서 B를 가립니다. 추적기는 프레임마다 나온 개체(여기서는 박스)를 이전 프레임의 트랙과 IoU가 큰 쌍부터 짝지어 ID를 이어 붙입니다.

  • IoU 기준: 겹침이 이보다 작으면 같은 개체로 보지 않고 새 ID를 만든다
  • 트랙 유지: 탐지가 끊겨도 트랙을 지우지 않고 기다리는 프레임 수
  • 위치 예측: 끊긴 동안 마지막 속도로 박스를 옮겨 둘지 정한다. SORT의 칼만 필터를 등속 모델로 단순화한 것이다

가정: B는 절반 이상 가려지면 탐지되지 않고, 탐지될 때는 가려진 부분까지 포함한 전체 박스가 나옵니다. A는 프레임당 1.5칸, B는 0.5칸 오른쪽으로 움직입니다. 짝짓기는 SORT의 헝가리안 매칭 대신 IoU가 큰 쌍부터 고르는 탐욕적 방식입니다.

Semantic Segmentation: 픽셀마다 클래스 하나 (torchvision DeepLabv3)
import torch
from torchvision.io import read_image
from torchvision.models.segmentation import deeplabv3_resnet50, DeepLabV3_ResNet50_Weights

weights = DeepLabV3_ResNet50_Weights.DEFAULT
model = deeplabv3_resnet50(weights=weights).eval()
img = read_image("street.jpg")                       # [3, H, W] uint8
x = weights.transforms()(img).unsqueeze(0)           # 크기 조정·정규화 → [1, 3, H', W']
with torch.inference_mode():
    logits = model(x)["out"]                         # [1, 21, H', W'] 픽셀마다 클래스 점수
sem = logits.argmax(dim=1)[0]                        # [H', W'] 픽셀마다 클래스 번호 하나
car = weights.meta["categories"].index("car")
print((sem == car).sum().item(), "픽셀이 car")        # 차가 몇 대든 픽셀 수만 나온다
Instance Segmentation: 개체마다 (클래스, 마스크, 신뢰도) (torchvision Mask R-CNN)
from collections import Counter
from torchvision.models.detection import maskrcnn_resnet50_fpn_v2, MaskRCNN_ResNet50_FPN_V2_Weights

weights = MaskRCNN_ResNet50_FPN_V2_Weights.DEFAULT
model = maskrcnn_resnet50_fpn_v2(weights=weights).eval()
with torch.inference_mode():
    out = model([weights.transforms()(img)])[0]      # 이미지 리스트를 받아 이미지마다 dict 하나
keep = out["scores"] > 0.5
names = [weights.meta["categories"][i] for i in out["labels"][keep].tolist()]
masks = out["masks"][keep, 0] > 0.5                  # [N, H, W] 개체마다 마스크 한 장
seen = Counter()
for name, m in zip(names, masks):
    seen[name] += 1
    print(f"{name} #{seen[name]}: {m.sum().item()} px")   # car #1, car #2 … 마스크끼리 겹칠 수 있다
Panoptic으로 합치기: Panoptic FPN 논문의 후처리 규칙을 단순화한 것
import numpy as np

def merge_panoptic(sem, instances, stuff_ids, overlap_thr=0.5, min_stuff_area=64):
    pan = np.zeros(sem.shape, dtype=np.int64)        # 0 = 아직 주인 없는 픽셀
    segments, next_id = [], 1
    for inst in sorted(instances, key=lambda d: -d["score"]):    # 신뢰도 높은 개체부터
        free = inst["mask"] & (pan == 0)
        if free.sum() < overlap_thr * inst["mask"].sum():         # 절반 넘게 이미 차지됨 → 버림
            continue
        pan[free] = next_id
        segments.append({"id": next_id, "category": inst["label"], "isthing": True})
        next_id += 1
    for c in stuff_ids:                                           # 남은 픽셀은 stuff 클래스로
        region = (sem == c) & (pan == 0)
        if region.sum() >= min_stuff_area:                        # 너무 작은 조각은 버림
            pan[region] = next_id
            segments.append({"id": next_id, "category": c, "isthing": False})
            next_id += 1
    return pan, segments                             # 픽셀마다 세그먼트 ID 정확히 하나

원래 · 작성 답안비교표 "출력 단위 — 픽셀별 클래스와 개체 ID", 그리고 ② Instance Segmentation 그림에 [도로] 영역을 그려 넣은 것

정정Instance Segmentation의 출력은 픽셀 지도가 아니라 검출한 개체 N개의 목록입니다. 개체마다 클래스, 마스크 한 장, 신뢰도가 나옵니다.

  • 도로·하늘 같은 stuff는 출력하지 않는다. 그림 ②의 [도로]는 빠져야 한다.
  • 마스크는 개체마다 따로 예측하므로 서로 겹칠 수 있고, 어느 마스크에도 속하지 않는 픽셀도 있다.

"모든 픽셀에 클래스와 개체 ID가 정확히 하나씩" 붙는 형식은 Panoptic Segmentation의 정의입니다(위 그림 ③).

원래 · 작성 답안픽셀 실험 표 "D | 도로 | 배경 또는 도로"

정정Instance 결과에서 D는 어떤 마스크에도 속하지 않습니다(출력 없음). D가 '도로'라는 정보는 Semantic이나 Panoptic 결과에서만 나옵니다.

원래 · 작성 답안즉, 두 자동차가 붙어 있거나 겹쳐 보여도 각각 독립된 물체로 인식할 수 있습니다.

정정그렇게 하도록 학습하는 것이지 보장되지는 않습니다. 같은 클래스 물체가 맞닿거나 크게 겹치는 장면은 Instance Segmentation의 대표적인 실패 사례입니다.

  • Mask R-CNN 계열: 박스끼리의 IoU가 NMS 기준(torchvision 기본 0.5)을 넘으면 신뢰도가 낮은 박스를 지운다. 뒤에서 크게 가려진 차가 통째로 사라질 수 있다.
  • 맞닿은 경계: 붙은 부분의 픽셀이 다른 개체로 넘어가기 쉽다.

그래서 혼잡한 장면을 위한 Soft-NMS(Bodla 외, 2017) 같은 변형과, 가려진 부분까지 예측하는 amodal 분할이 따로 연구됩니다.

원래 · 작성 답안“자동차인지 판단하는 것은 객체 탐지만으로 충분하다”라고 설명하면 정확하지 않습니다. 픽셀 단위의 영역을 요구하므로 분할 기법을 사용해야 합니다.

정정첫 번째 문제(픽셀의 클래스)에는 맞는 말입니다. 하지만 두 번째 문제인 "서로 다른 개체로 구별"은 객체 탐지로도 풀립니다. 탐지는 개체마다 박스 하나와 클래스를 내므로 차 #1·#2가 이미 구분됩니다.

마스크가 꼭 필요한 것은 개체의 정확한 모양이 중요할 때입니다. 박스가 크게 겹치는 경우나 차체 윤곽, 열린 문이 그 예입니다. 실제 자율주행 인식은 카메라와 라이다를 함께 쓰는 3D 박스 탐지 + 추적이 중심이고, nuScenes·Waymo Open Dataset의 대표 과제도 3D 탐지와 추적입니다.

보충 · Panoptic의 평가 지표

PQ = SQ × RQ, mIoU로는 개체 구분이 안 보인다

Panoptic Segmentation과 PQ(Panoptic Quality)는 Kirillov 외(2019)가 함께 제안했습니다. 클래스마다 IoU > 0.5인 예측·정답 세그먼트를 짝지은 뒤, 두 항으로 나눠 읽습니다.

  • SQ(분할 품질): 짝지은 세그먼트들의 평균 IoU, 즉 모양이 얼마나 정확한가
  • RQ(인식 품질): TP / (TP + ½FP + ½FN), 즉 개체를 빠짐없이 하나씩 찾았는가

IoU 기준이 0.5보다 크면 한 정답에 짝지어질 수 있는 예측이 최대 하나라서 매칭이 유일하게 정해집니다. COCO Panoptic은 things 80개와 stuff 53개, 모두 133개 클래스로 평가합니다. 실험 2의 '두 차 합침'처럼 mIoU는 1인데 PQ만 떨어지는 경우가 바로 개체 구분 실패입니다.

보충 · Instance Segmentation을 푸는 세 갈래

먼저 찾고 칠하기, 칠하고 묶기, 쿼리로 한 번에

  • 탐지 후 분할(top-down): Mask R-CNN은 박스를 먼저 찾고, RoIAlign으로 박스 안 특징을 뽑아 개체마다 28 × 28 마스크를 예측한다.
  • 분할 후 묶기(bottom-up): Panoptic-DeepLab은 Semantic 결과와 함께 개체 중심 지도와 각 픽셀에서 중심까지의 오프셋을 예측해, 같은 중심을 가리키는 픽셀을 한 개체로 묶는다. 실험 1의 연결 요소를 학습된 묶음 규칙으로 바꾼 셈이다.
  • 쿼리 기반: Mask2Former는 학습되는 쿼리 N개가 각자 마스크 하나와 클래스 하나를 예측한다. 같은 구조로 Semantic·Instance·Panoptic을 모두 푼다.
보충 · 학습과 지표에서 주의할 점

도로는 크고 사람은 작다

도로 장면은 도로·하늘 픽셀이 압도적으로 많고, 멀리 있는 보행자는 수십 픽셀에 불과합니다. 그래서 픽셀 정확도만으로는 성능을 판단할 수 없습니다. 실험 2에서 사람을 통째로 놓쳐도 픽셀 정확도는 2.4%p만 떨어집니다.

  • 지표: 클래스를 같은 무게로 평균하는 mIoU, 개체 단위인 Mask AP·PQ를 본다.
  • 손실: 픽셀별 교차 엔트로피에 클래스 가중치를 주거나, Dice·Focal 손실을 섞어 작은 클래스의 비중을 키운다.
  • 해상도: 작은 물체는 1픽셀 오차에도 IoU가 크게 떨어진다(실험 2의 경계 번짐). 출력 해상도를 지키는 디코더가 중요한 이유다.
보충 · 객체 추적은 무엇으로 짝짓나

위치 예측, 겹침, 외형

  • SORT(Bewley 외, 2016): 칼만 필터로 다음 위치를 예측하고, 예측 박스와 탐지 박스의 IoU로 헝가리안 매칭을 한다.
  • DeepSORT(Wojke 외, 2017): 외형 임베딩을 더해, 오래 가려졌다 나타난 개체도 같은 개체로 다시 찾는다.
  • ByteTrack(Zhang 외, 2022): 신뢰도가 낮은 탐지도 버리지 않고 2차 매칭에 써서 가려진 개체를 덜 놓친다.

실험 3은 이 중 SORT의 뼈대만 남긴 것입니다. ID가 끊기면 같은 차가 두 대로 기록되어, 속도와 궤적 예측이 처음부터 다시 시작됩니다.

픽셀이 차인지 도로인지 사람인지는 Semantic Segmentation으로 풉니다. DeepLabv3+나 U-Net 같은 인코더-디코더 모델이 모든 픽셀에 클래스를 하나씩 붙이고, 픽셀별 교차 엔트로피로 학습해 mIoU로 평가합니다. 다만 같은 클래스는 모두 같은 라벨이라서, 차 두 대가 맞닿으면 몇 대인지 알 수 없습니다.

왼쪽 차와 오른쪽 차를 구별하는 것은 Instance Segmentation으로 풉니다. Mask R-CNN처럼 개체를 먼저 찾고 개체마다 마스크를 따로 예측하므로 차 #1, 차 #2가 나오고, Mask AP로 평가합니다. 도로 같은 배경은 출력하지 않고, 모양까지 필요 없다면 객체 탐지 박스로도 개체는 구분됩니다.

자율주행에서는 두 결과가 모두 필요해서, 모든 픽셀에 클래스와 개체 ID를 하나씩 주는 Panoptic Segmentation으로 합치고 PQ로 평가합니다. 영상에서는 객체 추적으로 위치 예측과 IoU를 써서 프레임 사이 개체를 짝짓습니다. 가려졌다 다시 나타난 차에도 같은 ID를 유지해야 속도와 궤적을 예측할 수 있기 때문입니다.
