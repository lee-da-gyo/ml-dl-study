Q1
실습 해설

딥러닝과 머신러닝 간의 포함관계에 대해 설명해주세요.

한 줄 요약

딥러닝은 머신러닝의 하위 분야다. 더 정확히는 인공지능 ⊃ 머신러닝 ⊃ 표현 학습 ⊃ 딥러닝이다.

둘을 가르는 기준은 "신경망을 쓰는가"보다 입력을 어떤 특징으로 바꿀지를 사람이 정하는가, 여러 층이 데이터에서 직접 배우는가이다.

그래서 모든 딥러닝은 머신러닝이지만, 선형 회귀·결정 트리·SVM처럼 딥러닝이 아닌 머신러닝도 많다.

같은 데이터에 세 모델을 이 페이지에서 Adam으로 직접 학습합니다.

  • ① 원래 좌표 (x₁, x₂)만 쓴 로지스틱 회귀
  • ② 사람이 만든 특징 하나(동심원이면 x₁²+x₂², XOR이면 x₁·x₂)를 더한 로지스틱 회귀
  • ③ 원래 좌표만 받는 은닉층 16개짜리 신경망(MLP)

핵심 전통적인 머신러닝과 딥러닝 비교 (경향)

구분전통적인 머신러닝딥러닝
대표 모델선형·로지스틱 회귀, 결정 트리, SVM, k-NN, 랜덤 포레스트, GBDTMLP, CNN, RNN, 트랜스포머
특징(표현)사람이 만든 특징에 기대는 비중이 크다. 단, 트리 계열은 원래 열에서 상호작용을 스스로 찾는다여러 층이 특징을 학습한다. 대신 구조(합성곱, 어텐션)와 데이터 설계가 사람 몫이다
잘 맞는 데이터표 형태의 정형 데이터. 중간 규모 정형 데이터에서는 지금도 GBDT가 신경망보다 강한 경우가 많다이미지·음성·텍스트처럼 원시 신호가 큰 비정형 데이터
데이터 요구량비교적 적다처음부터 학습하면 많이 필요하다. 사전 학습 모델을 가져와 미세 조정하면 적은 데이터로도 된다
계산 비용CPU로 충분한 경우가 많다GPU·TPU가 사실상 필요하다
설명 가능성선형 모델·얕은 트리는 높다. 큰 앙상블·커널 SVM은 이미 해석이 어렵다낮다. 사후 설명 기법(SHAP, Grad-CAM 등)에 의존한다

표의 내용은 절대 규칙이 아니라 경향입니다. 정형 데이터 비교 연구(Grinsztajn 외, NeurIPS 2022)에서도 중간 규모(약 1만 행) 데이터에서는 트리 기반 모델이 대체로 앞섰습니다.

2 · 핵심 정리와 보충
정정 · 실습 해설의 과장된 일반화 두 가지
원래 · 실습 해설(딥러닝은) 사람이 개입해 특징을 설계하지 않아도 되며, 대량의 데이터를 처리할수록 높은 성능을 발휘합니다.

정정줄어드는 것은 특징을 손으로 만드는 부담이지 사람의 개입이 아닙니다. 다음은 여전히 사람이 합니다.

  • 데이터 수집과 라벨링, 전처리
  • 모델 구조 선택 (이미지에 합성곱을 쓰는 것도 사람이 넣는 사전 지식입니다)
  • 손실 함수와 평가 지표 설계

작성 답안은 이 점을 이미 바르게 보완했습니다. "데이터가 많을수록 성능이 높다"도 경향일 뿐이고, 데이터가 적어도 사전 학습 모델을 미세 조정하면 좋은 성능을 낼 수 있습니다.

원래 · 실습 해설(머신러닝은) 데이터를 처리하기 위해 사람이 직접 중요한 특징(feature)을 설계하는 작업이 필요합니다.

정정전통적인 머신러닝이 사람이 만든 특징에 더 의존하는 경향이 있을 뿐, 필수 조건은 아닙니다. 결정 트리와 GBDT는 원래 열을 그대로 넣어도 비선형 관계와 상호작용을 학습합니다.

또 머신러닝은 딥러닝을 포함하므로, "머신러닝은 특징 설계가 필요하다"는 문장은 "딥러닝이 아닌 전통적인 머신러닝은"으로 범위를 좁혀야 맞습니다.

보충 · 신경망 ≠ 딥러닝

층이 하나면 '깊지' 않다

은닉층이 없는 퍼셉트론은 신경망이지만 사실상 선형 분류기이고, 시그모이드 출력 하나짜리 신경망은 로지스틱 회귀와 같습니다. 실험 1의 ①이 바로 "층 하나짜리 신경망"입니다.

딥러닝의 "깊다"는 여러 층에 걸쳐 표현을 단계적으로 학습한다는 뜻입니다.

보충 · 학습 방식은 공유한다

지도·비지도·강화 학습은 둘 다 쓴다

지도·비지도·강화 학습은 머신러닝 전체의 학습 방식 분류이고, 딥러닝도 그대로 씁니다.

  • 지도: 이미지 분류
  • 비지도: 오토인코더
  • 강화: 알파고

딥러닝에서 특히 중요해진 것은 라벨 없이 데이터 자체에서 문제를 만드는 자기 지도 학습입니다. 언어 모델의 다음 단어 예측이 대표 예입니다.

보충 · 무엇을 고를까

데이터 형태가 먼저다

  • 정형 데이터 수천~수만 행: GBDT를 기준 모델로 시작한다.
  • 이미지·음성·텍스트: 사전 학습된 신경망에서 시작한다.
  • 해석이 법적으로 필요하면: 면접 2처럼 해석 가능한 모델이 우선이다.

딥러닝은 머신러닝의 하위 분야이고, 머신러닝은 인공지능의 하위 분야입니다. 머신러닝은 사람이 규칙을 직접 쓰는 대신 데이터에서 규칙을 학습하는 방법 전체이고, 딥러닝은 그중 여러 층의 신경망으로 입력의 표현까지 데이터에서 배우는 방법입니다.

전통적인 머신러닝은 HOG 특징이나 파생 변수처럼 사람이 만든 특징 위에서 모델을 학습하는 경향이 있고, 딥러닝은 특징을 만드는 층까지 종단 간으로 학습해 이미지·음성·텍스트에서 강합니다.

다만 사람의 역할이 사라지는 것은 아니어서 데이터, 구조, 손실과 평가는 여전히 설계해야 하고, 정형 데이터에서는 지금도 GBDT가 강한 경우가 많습니다. 그래서 모든 딥러닝은 머신러닝이지만, 모든 머신러닝이 딥러닝은 아닙니다.

2 · 핵심 정리와 보충
정정 · 실습 해설의 설명 중 사실과 다른 부분
원래드롭아웃은 과적합을 방지하기 위해 일부 뉴런을 랜덤하게 제거하는 방식이고

정정뉴런을 영구히 없애는 것이 아닙니다.

  • 학습할 때만: 매 스텝 새로 뽑은 일부 뉴런의 출력을 0으로 만들고, 남은 출력은 1/(1−p)배로 키워 기댓값을 맞춥니다(역 드롭아웃, Keras·PyTorch 방식).
  • 추론할 때: 모든 뉴런을 그대로 씁니다. 그래서 Keras는 model.fit() 중에만 드롭아웃이 켜지고 predict()·evaluate()에서는 꺼집니다.

뉴런이나 가중치를 실제로 없애는 것은 가지치기(pruning)라는 다른 기법입니다.

원래활성화 함수는 ReLU, sigmoid, tanh 등 여러 종류가 있는데, 문제의 특성과 데이터의 분포에 따라 적절히 선택해야 합니다.

정정은닉층과 출력층의 기준이 다릅니다.

  • 은닉층: 데이터 분포가 아니라 기울기가 잘 흐르는지로 고르며, ReLU 계열(트랜스포머는 GELU)이 기본입니다. 시그모이드·tanh는 깊은 망에서 기울기 소실을 일으키기 쉽습니다.
  • 출력층: 문제 유형이 정합니다(이진 분류 시그모이드, 다중 분류 소프트맥스, 회귀 항등 함수).

즉 "데이터 분포에 따라 고른다"는 기준은 어느 쪽에도 맞지 않습니다.

원래레이어 수가 너무 적으면 과소적합될 가능성이 있고, 너무 많으면 과적합이 발생할 수 있으므로

정정층을 많이 쌓을 때 먼저 생기는 문제는 과적합이 아니라 학습 자체가 어려워지는 것일 수 있습니다.

ResNet 논문(He 외, 2016)에서 잔차 연결 없는 56층 망은 20층 망보다 훈련 오차가 더 높았습니다. 이것은 외운 것이 아니라 최적화가 안 된 것이고, 잔차 연결과 정규화 층(배치·레이어 정규화)으로 해결합니다.

또 지금의 큰 신경망은 파라미터가 데이터보다 훨씬 많아도 규제·데이터 증강과 함께 잘 일반화합니다. 그래서 "크면 과적합"보다 "크면 계산이 늘고, 규제와 검증이 더 중요해진다"가 정확합니다.

보충 · 배치 크기는 먼저 고정한다

검증 성능용 튜닝 대상이 아니다

Google의 Deep Learning Tuning Playbook은 배치 크기를 하드웨어와 학습 시간으로 정하고, 검증 성능을 높이려고 튜닝하지 말라고 권합니다. 학습률·규제를 다시 맞추고 스텝 수가 충분하면 배치 크기가 달라도 비슷한 성능에 도달하기 때문입니다(Shallue 외, 2018).

배치를 k배로 키울 때 학습률도 k배로 하고 warm-up을 두는 선형 스케일링 규칙(Goyal 외, 2017)은 출발점일 뿐 항상 성립하지는 않습니다.

보충 · Adam과 L2는 다르다

AdamW를 쓰는 이유

  • SGD: 손실에 L2 항을 더하는 것과 가중치 감쇠가 같다.
  • Adam: L2 기울기도 적응형 분모로 나뉘어, 기울기가 큰 가중치일수록 덜 줄어든다.

감쇠를 갱신에서 분리한 AdamW(Loshchilov & Hutter, 2019)가 이를 바로잡았고, 실험 2도 AdamW 방식입니다.

또 우리말 "정규화"는 regularization(규제, 이 문항의 의미)과 normalization(배치 정규화, 입력 표준화)을 함께 가리키므로 영어로 구분해 두면 좋습니다.

보충 · 탐색 방법

격자보다 랜덤, 그다음 베이지안

중요한 하이퍼파라미터가 몇 개뿐일 때 격자 탐색은 같은 값을 반복해서 시도합니다. 랜덤 탐색은 같은 횟수로 각 축을 더 촘촘히 봅니다(Bergstra & Bengio, 2012, 실험 3).

  • 학습률·감쇠는 로그 척도로 뽑는다.
  • 시도 비용이 크면 Optuna 같은 베이지안 최적화나, 성능이 나쁜 시도를 일찍 끊는 Hyperband·ASHA를 쓴다.

보충 실무 튜닝 순서

평가 틀 고정훈련·검증·테스트 분할, 평가 지표, 기준 모델. 테스트는 마지막에 한 번만
구조·배치 크기 고정검증된 구조와 메모리에 맞는 배치 크기로 시작
학습률부터 탐색로그 척도로 넓게, 옵티마이저·스케줄과 함께
규제 조정훈련–검증 격차를 보며 드롭아웃·감쇠·증강, 조기 종료
Keras로 규제·조기 종료를 넣고, 학습률과 감쇠를 로그 척도로 랜덤 탐색하기
import numpy as np, keras
from keras import layers

def build(lr, wd, p, units):
    model = keras.Sequential([
        keras.Input(shape=(n_features,)),
        layers.Dense(units, activation="relu"),
        layers.Dropout(p),                                # 학습 중에만 켜진다
        layers.Dense(units, activation="relu"),
        layers.Dropout(p),
        layers.Dense(1, activation="sigmoid"),            # 출력층은 문제 유형으로 정해진다
    ])
    model.compile(optimizer=keras.optimizers.AdamW(learning_rate=lr, weight_decay=wd),
                  loss="binary_crossentropy", metrics=["accuracy"])
    return model

rng = np.random.default_rng(0)
stop = keras.callbacks.EarlyStopping(monitor="val_loss", patience=10, restore_best_weights=True)
results = []
for trial in range(20):
    hp = dict(lr=10 ** rng.uniform(-5, -2),               # 로그 척도
              wd=10 ** rng.uniform(-5, -1),
              p=rng.choice([0.0, 0.2, 0.5]),
              units=int(rng.choice([64, 128, 256])))
    h = build(**hp).fit(X_tr, y_tr, validation_data=(X_val, y_val), epochs=300,
                        batch_size=128, callbacks=[stop], verbose=0)
    results.append((min(h.history["val_loss"]), hp))    # 테스트 세트는 여기서 쓰지 않는다
best = min(results, key=lambda r: r[0])

하이퍼파라미터는 가중치처럼 학습되는 값이 아니라 학습 전에 정하고 검증 데이터로 고르는 설정값입니다.

크게 네 묶음으로, 층 수와 너비·은닉층 활성화 같은 모델 구조, 학습률·옵티마이저·스케줄·배치 크기 같은 최적화, 드롭아웃·가중치 감쇠·조기 종료 같은 규제, 그리고 데이터 증강이 있습니다.

가장 영향이 큰 것은 대개 학습률이라 로그 척도로 가장 먼저 넓게 탐색하고, 배치 크기는 메모리와 속도로 먼저 정한 뒤 바꾸면 학습률을 다시 맞춥니다. 드롭아웃은 학습 중에만 무작위로 출력을 끄는 규제이고, Adam을 쓸 때는 AdamW로 감쇠를 분리합니다.

탐색은 격자보다 랜덤이나 베이지안 최적화가 효율적이고, 모든 선택은 검증 데이터로 하며 테스트는 마지막에 한 번만 씁니다.

pipe = make_pipeline(StandardScaler(), model)         # 전처리는 폴드마다 훈련 부분에서만 fit

정정 · 누수가 점수를 움직이는 방향을 구분해야 한다
원래 · 작성 답안훈련 데이터와 테스트 데이터가 중복되지 않았는가? … 전체 데이터에 스케일링이나 결측치 처리를 먼저 적용한 뒤 데이터를 나눴다면 데이터 누수가 발생할 수 있습니다. (테스트 70%의 원인 후보로 제시)

정정점검 항목 자체는 맞지만, 이 두 가지는 테스트 점수를 부풀리는 방향으로 작용합니다. 테스트 정보가 훈련에 섞이면 테스트가 실제보다 좋아 보이므로 "테스트가 낮다"는 증상의 원인이 될 수 없고, 오히려 실제 격차가 70%보다 더 클 수 있다는 경고입니다.

이 증상과 맞는 것은 훈련 점수만 부풀리는 누수입니다.

  • 예측 시점 이후에 생기는 특징 (실험 4의 해지 상담 기록)
  • 행 자신의 정답이 들어간 타깃 인코딩 (out-of-fold 없이 계산)
  • 정답과 거의 일대일인 ID성 특징

반대로 테스트 점수를 낮추는 측정 오류는 테스트에 따로 fit_transform을 한 경우처럼 전처리가 서로 다른 경우입니다.

보충 · 99%가 문제인 것은 아니다

격차와 상한을 같이 본다

트리 앙상블이나 큰 신경망은 훈련 정확도 100%도 흔합니다. 문제는 격차입니다.

또 라벨 잡음이 크면 테스트 정확도의 상한 자체가 낮습니다. 실험 4는 라벨 잡음이 10%라 어떤 모델도 테스트 90%를 넘기 어렵습니다. 같은 데이터를 사람이 다시 라벨링했을 때의 일치율로 상한을 가늠합니다.

보충 · 학습 로그의 훈련 정확도

드롭아웃이 켜진 상태의 평균이다

Keras fit()이 출력하는 훈련 정확도는 드롭아웃·증강이 켜진 상태에서, 에포크 동안 변하는 가중치로 잰 평균입니다.

테스트와 비교하려면 학습이 끝난 모델로 evaluate(X_train, y_train)을 다시 재야 합니다.

보충 · 개선 순서

데이터 → 분할 → 모델

  • 먼저: 누수 특징 제거와 분할 수정
  • 그다음 과적합이면: 규제(드롭아웃·감쇠·깊이 제한), 조기 종료, 데이터 증강이나 추가 수집, 앙상블

매번 CV와 검증 세트로만 판단합니다. 테스트 세트를 보면서 고치면 테스트에도 과적합합니다.

훈련 99%, 테스트 70%라면 과적합을 가장 먼저 의심하지만, 바로 규제를 늘리기 전에 세 가지를 확인하겠습니다.

첫째, 다수 클래스 비율과 혼동행렬로 70%가 기준선보다 나은지, 훈련 점수를 테스트와 같은 조건과 같은 전처리로 쟀는지 봅니다. 둘째, 훈련 데이터로 교차 검증을 해서 CV 점수가 테스트처럼 낮으면 과적합, CV는 높은데 테스트만 낮으면 누수나 분포 차이로 봅니다. 셋째, 예측 시점에 알 수 없는 특징이나 out-of-fold 없이 만든 타깃 인코딩을 찾고, 적대적 검증으로 훈련과 테스트가 구분되는지 확인합니다.

과적합이면 모델 복잡도를 줄이고 드롭아웃·가중치 감쇠·조기 종료, 데이터 증강을 적용하고, 누수나 분포 변화면 특징과 분할 방식을 고칩니다. 판단은 끝까지 검증 데이터로 하고, 테스트는 마지막에만 씁니다.
