핵심 정상 GAN과 모드 붕괴

형태보이는 모습확인 방법
완전 붕괴모든 z가 거의 같은 얼굴 하나를 만든다무작위 z 64개의 결과를 한 장에 모아 보면 바로 보인다
부분 붕괴 (모드 누락)얼굴은 여러 가지지만 특정 유형(노인, 측면, 안경 등)이 아예 나오지 않는다눈으로는 놓치기 쉽다. Recall, 속성 분류기로 본 속성 분포를 실제 데이터와 비교
모드 호핑학습 시점마다 출력이 한 유형에서 다른 유형으로 통째로 옮겨 다닌다같은 고정 z 격자를 체크포인트마다 저장해 나란히 비교

핵심 왜 생기나: 판별자는 샘플을 하나씩 채점한다

LG = − 𝔼z [ log D(G(z)) ]   ← 샘플마다 따로 매긴 점수의 평균

이 손실에는 샘플끼리 비교하는 항이 없습니다. 판별자 D를 고정한 채 생성자만 끝까지 최적화하면, 모든 z를 D가 가장 진짜라고 채점하는 점 x* = argmax D(x)로 보내는 것이 최적입니다. Goodfellow 외(2014)도 원 논문에서, D를 갱신하지 않은 채 G만 너무 많이 학습하면 G가 많은 z를 같은 x로 보내게 된다고 경고했습니다.

판별자가 뒤따라와 x*를 가짜로 배우면 생성자는 다음으로 점수가 높은 곳으로 통째로 옮깁니다. 이것이 모드 호핑이고, 이 술래잡기가 수렴하지 못한 채 한쪽으로 굳으면 붕괴입니다.

∇θ 𝔼z[ −log D*(Gθ(z)) ] = ∇θ [ KL(Pg ‖ Pr) − 2·JSD(Pg ‖ Pr) ]

목적함수의 방향도 붕괴 쪽으로 기울어 있습니다. Arjovsky & Bottou(2017)는 판별자가 최적일 때 실무에서 쓰는 비포화 손실의 기울기가 위 식과 같음을 보였습니다. 여기 들어 있는 역방향 KL은 다음처럼 벌점이 비대칭입니다.

  • 진짜 데이터가 없는 곳에 샘플을 만들면 큰 벌점 (Pr → 0이면 log(Pg/Pr) → ∞)
  • 진짜 모드 하나를 통째로 빠뜨리면 작은 벌점 (Pg → 0이면 그 구간의 기여도 → 0)

그래서 "확실한 몇 곳만 정확히" 만드는 해를 선호합니다. 실험 1에서 직접 확인해 보세요.

실험 1 봉우리 두 개를 가우시안 하나로 맞추면: 목적함수마다 고르는 해가 다르다 예시 분포 · 1차원

실제 분포(Pr)는 −d와 +d에 있는 봉우리 두 개(표준편차 1)입니다. 생성 분포는 가우시안 하나 N(μ, σ)라서 둘을 동시에 정확히 맞출 수 없습니다. 네 가지 목적함수를 각각 최소로 만드는 μ, σ를 이 페이지에서 격자 탐색으로 찾습니다.

  • 순방향 KL(Pr ‖ Pg): 최대우도 학습과 같은 목적 (VAE · 확산 모델 계열)
  • 역방향 KL(Pg ‖ Pr)
  • JSD: 원래 GAN 논문의 이론적 목적
  • 비포화 GAN: KL(Pg ‖ Pr) − 2·JSD, 실무 GAN 손실의 실제 목적

핵심 대응 기법 지도

원인이 여러 겹이므로 한꺼번에 다 넣지 말고 점검 → 균형 → 손실 · 정규화 → 다양성 장치 → 데이터 순서로 하나씩 바꾸며 비교해야 무엇이 효과였는지 알 수 있습니다.

단계기법원리주의
점검데이터 · 로더 · z 샘플링붕괴처럼 보이는 구현 오류를 먼저 걸러 낸다고정 z와 무작위 z를 둘 다 본다. 고정 z만 보면 전체 다양성을 판단할 수 없다
균형TTUR (Heusel 외 2017)생성자와 판별자에 서로 다른 학습률을 준다대표 설정(SAGAN)은 오히려 판별자 쪽이 더 크다(D 4×10⁻⁴, G 1×10⁻⁴)
D:G 업데이트 비한쪽이 너무 앞서 나가지 않게 갱신 횟수를 맞춘다어느 쪽으로 기울어도 문제가 될 수 있다. 실험 2에서 판별자만 5번씩 갱신하면 모드가 줄어든다. 반면 WGAN 계열은 손실이 달라 비평자를 의도적으로 5번씩 갱신한다
손실 · 정규화비포화 손실 + R1 (Mescheder 외 2018)실제 이미지에서 판별자 기울기의 크기 ‖∇D(x)‖²에 벌점을 줘 판별자를 매끄럽게 한다StyleGAN 계열 얼굴 생성의 기본 조합
Spectral Norm (Miyato 외 2018) + Hinge 손실각 층의 가중치를 최대 특잇값으로 나눠 층마다 립시츠 상수를 1 이하로 묶는다SAGAN · BigGAN이 쓴 조합
WGAN-GP (Gulrajani 외 2017)Wasserstein 거리를 쓰고, 실제 · 가짜 사이 보간점에서 ‖∇D‖가 1이 되도록 벌점을 준다비평자에 배치 정규화를 쓰면 안 된다(샘플별 기울기 벌점과 충돌, 레이어 정규화로 대체). 붕괴를 없애 주는 보장은 없다
다양성 장치Minibatch StdDev (Karras 외 2018)판별자 마지막 블록 직전에 샘플 간 특징 표준편차의 평균을 특징 맵 한 장으로 붙여, 다양성이 낮은 배치를 판별자가 알아보게 한다ProGAN · StyleGAN에 기본 포함, 비용이 거의 없다
Minibatch Discrimination · Feature Matching (Salimans 외 2016)배치 안 샘플끼리의 유사도를 판별자 특징으로 쓰거나, 생성자가 판별자 중간 특징의 평균을 실제 데이터와 맞추게 한다Feature Matching은 다양성은 늘리지만 이미지 품질이 떨어질 수 있다
Unrolled GAN (Metz 외 2017)생성자가 판별자의 다음 몇 스텝 반응까지 미분해, 당장만 속이는 방향을 피한다펼친 스텝 수만큼 계산이 늘어 큰 모델에는 잘 쓰지 않는다
Mode-seeking 손실 (Mao 외 2019)두 z의 거리 대비 두 출력의 거리를 키워, 다른 z가 다른 출력을 만들게 한다조건 입력이 강해 z를 무시하는 조건부 GAN을 위해 제안됐다
데이터ADA (Karras 외 2020) · DiffAugment (Zhao 외 2020)판별자에 들어가는 실제 · 가짜 이미지에 같은 미분 가능한 증강을 적용해, 적은 데이터에서 판별자가 학습 이미지를 외우는 것을 막는다실제 이미지에만 증강을 걸면 생성자가 증강까지 따라 한다(아래 정정)
판별자에 넣는 Minibatch StdDev 층 (StyleGAN2 구현과 같은 방식, 특징 맵 1장)
import torch
from torch import nn

class MinibatchStdDev(nn.Module):
    def __init__(self, group_size=4):
        super().__init__()
        self.group_size = group_size

    def forward(self, x):                                # x: (N, C, H, W), 판별자 마지막 블록 직전
        n, c, h, w = x.shape
        g = min(self.group_size, n)                      # N은 g로 나누어떨어져야 한다
        y = x.reshape(g, -1, c, h, w)                    # (그룹 크기, 그룹 수, C, H, W)
        y = (y.var(dim=0, unbiased=False) + 1e-8).sqrt() # 그룹 안 샘플 간 표준편차
        y = y.mean(dim=[1, 2, 3])                        # 그룹마다 숫자 하나
        y = y.reshape(-1, 1, 1, 1).repeat(g, 1, h, w)    # 같은 그룹 샘플에 되돌려 붙인다
        return torch.cat([x, y], dim=1)                  # 채널 하나 추가: (N, C + 1, H, W)
비포화 손실 + R1 규제, TTUR, 고정 z로 다양성 기록하기
import torch
import torch.nn.functional as F

opt_g = torch.optim.Adam(G.parameters(), lr=1e-4, betas=(0.0, 0.9))
opt_d = torch.optim.Adam(D.parameters(), lr=4e-4, betas=(0.0, 0.9))   # TTUR: SAGAN 설정
fixed_z = torch.randn(64, z_dim, device=device)          # 학습 내내 같은 z로 경과 비교

def d_step(real, gamma=10.0):
    real = real.detach().requires_grad_(True)
    fake = G(torch.randn(real.size(0), z_dim, device=device)).detach()
    out_real, out_fake = D(real), D(fake)
    loss = F.softplus(-out_real).mean() + F.softplus(out_fake).mean()
    grad, = torch.autograd.grad(out_real.sum(), real, create_graph=True)
    r1 = grad.pow(2).flatten(1).sum(1).mean()            # 실제 이미지에서 ‖∇D(x)‖²
    opt_d.zero_grad(set_to_none=True)
    (loss + gamma / 2 * r1).backward()
    opt_d.step()

def g_step(batch_size):
    z = torch.randn(batch_size, z_dim, device=device)    # 배치마다 새로 뽑는다
    loss = F.softplus(-D(G(z))).mean()                   # 비포화 손실 −log D(G(z))
    opt_g.zero_grad(set_to_none=True)
    loss.backward()
    opt_g.step()

@torch.no_grad()
def diversity_log():
    fixed = G(fixed_z)                                   # 체크포인트끼리 나란히 저장해 비교
    rand = G(torch.randn(64, z_dim, device=device))
    spread = torch.pdist(rand.flatten(1)).mean().item()  # 배치 안 평균 거리: 계속 줄면 경고
    return fixed, spread
실험 3 FID · Precision · Recall이 각각 무엇을 놓치는지 보기 예시 데이터 · 2차원, 봉우리 8개

실제 데이터는 반지름 2인 원 위의 봉우리 8개(표준편차 0.1)입니다. 생성 분포를 골라 세 지표를 이 페이지에서 계산합니다. 실제 FID는 Inception 신경망의 2,048차원 특징으로 계산하지만, 여기서는 좌표 자체를 특징으로 씁니다.

  • FID: 두 특징 분포를 각각 가우시안으로 보고 평균과 공분산만 비교합니다. ‖μr − μg‖² + Tr(Σr + Σg − 2(ΣrΣg)1/2), 낮을수록 좋습니다.
  • Precision: 생성 샘플 중 실제 데이터 영역 안에 든 비율, 즉 품질입니다.
  • Recall: 실제 샘플 중 생성 데이터 영역 안에 든 비율, 즉 다양성 · 포괄 범위입니다.

영역은 Kynkäänniemi 외(2019) 방식으로, 각 샘플에서 같은 집합의 3번째 최근접 이웃까지를 반지름으로 하는 원들의 합집합입니다.

2 · 핵심 정리와 보충
정정 · 작성 답안에서 바로잡을 부분
원래 · 작성 답안Minibatch Standard Deviation: 배치의 특징 분산을 판별자 입력에 추가

정정판별자 입력이 아니라 마지막 블록 직전의 특징 맵에 붙입니다. 또 분산 자체가 아니라 샘플 간 표준편차를 모든 특징 · 위치에 걸쳐 평균한 숫자 하나를 특징 맵 한 장으로 복제해 이어 붙입니다(ProGAN, Karras 외 2018).

작성 답안의 최종 요약표("판별자의 후반부 특징에 추가")는 맞게 썼으므로, 본문 표와 서로 어긋났던 부분입니다.

원래 · 작성 답안ADA나 DiffAugment를 사용할 수 있습니다. … 단, 얼굴의 의미를 훼손하는 지나친 회전이나 변형은 피해야 합니다.

정정주의할 점은 의미 훼손이 아니라 증강 누출(leaking)입니다. ADA · DiffAugment는 판별자에 들어가는 실제와 가짜 모두에 같은 증강을 걸기 때문에, ADA 논문은 90° 회전 같은 강한 변형도 썼습니다. 적용 확률 p를 약 0.8보다 낮게 두면 생성자가 증강을 따라 하지 않습니다.

반대로 데이터셋의 실제 이미지에만 증강을 걸면 생성자는 "회전된 얼굴도 진짜"라고 배워 회전된 얼굴을 만들어 냅니다. 이때는 좌우 반전처럼 원래 분포에 실제로 있을 법한 변형만 써야 합니다.

보충 · 균형은 양방향으로 본다

"판별자를 약하게"만이 답은 아니다

작성 답안의 처방(판별자 학습률 · 업데이트 횟수 낮추기)은 판별자가 앞설 때 맞는 방향입니다. 실험 2에서도 판별자만 5번씩 갱신하면 모드가 줄어듭니다. 다만 반대 방향도 원인이 됩니다.

  • 판별자가 너무 앞설 때: 생성자 기울기가 불안정해지고 모드를 놓친다.
  • 생성자가 너무 앞설 때: 생성자가 낡은 판별자의 최고점으로 몰린다. 원 논문(Goodfellow 외 2014)이 경고한 붕괴 경로다.

그래서 TTUR의 대표 설정(SAGAN)은 오히려 판별자 학습률을 4배 크게 줍니다. TTUR은 "판별자를 늦추는 기법"이 아니라 두 학습률을 따로 맞추는 기법이고, 어느 쪽을 줄일지는 D 출력 분포와 고정 z 격자를 보고 정합니다.

보충 · 손실 값으로 균형을 판단하지 않는다

숫자보다 출력과 지표

GAN의 생성자 · 판별자 손실은 서로를 기준으로 매긴 값이라, 학습이 잘 돼도 내려가지 않고 붕괴가 진행돼도 멀쩡해 보일 수 있습니다. 두 손실이 비슷해야 정상이라는 기준도 없습니다.

그래서 고정 z 격자 이미지, 배치 안 평균 거리, 일정 간격의 FID · Precision · Recall을 함께 기록해 판단합니다.

보충 · 비교 실험은 시드 여러 개로

GAN은 시드에 따라 결과가 크게 흔들린다

Lucic 외(2018, "Are GANs Created Equal?")는 같은 모델도 시드와 하이퍼파라미터에 따라 FID가 크게 달라서, 충분히 탐색하면 여러 GAN 변형의 차이 대부분이 사라진다고 보고했습니다.

"시드 하나로 기준 모델과 기법 하나를 비교"하면 우연을 효과로 착각하기 쉽습니다. 설정마다 시드를 3개 이상 돌려 평균과 흩어짐을 같이 보세요. 실험 2의 "시드 4개" 칸이 그 차이를 보여 줍니다.

보충 · 지표를 잴 때의 함정

FID는 표본 수와 특징 추출기에 따라 달라진다

  • 표본 수: FID는 표본이 적을수록 커지는 편향이 있어, 같은 개수(보통 50,000장)로만 비교합니다. 실험 3에서 실제 vs 실제 FID가 0이 아닌 이유입니다.
  • 구현: 이미지 크기 조정 방식이나 Inception 가중치가 다르면 숫자가 달라지므로, 같은 구현으로 잰 값끼리만 비교합니다.
  • 두 숫자로: FID 하나로는 품질과 다양성 중 무엇이 문제인지 모릅니다. Precision과 Recall을 나눠 봐야 붕괴를 특정할 수 있습니다.
보충 · 다양성이 최우선이라면

우도 기반 생성 모델이라는 선택지

VAE와 확산 모델은 데이터 우도(또는 그 하한)를 키우는 순방향 KL 계열 목적으로 학습합니다. 실험 1에서 보듯 모드를 빠뜨리면 손해가 커서 모드 붕괴가 잘 생기지 않습니다.

대신 VAE는 흐릿해지기 쉽고, 확산 모델은 샘플링에 여러 단계가 필요해 느립니다. GAN의 장점(한 번에 생성 · 선명함)이 꼭 필요한지 먼저 따져 볼 만합니다.

서로 다른 잠재벡터를 넣어도 비슷한 얼굴만 나온다면 모드 붕괴로 보겠습니다. 생성자의 손실은 샘플마다 판별자가 진짜라고 보는지만 따지고 샘플끼리 다른지는 따지지 않아서, 판별자가 가장 진짜라고 믿는 몇 가지 얼굴로 몰리는 것이 생성자에게 가장 쉬운 해이기 때문입니다.

먼저 처음부터 비슷했는지 확인해서, z를 매번 새로 뽑는지와 데이터 로더 같은 구현 문제를 걸러 내겠습니다. 그다음 고정 z 격자를 체크포인트마다 저장해 붕괴인지 모드 호핑인지 보고, Precision과 Recall을 따로 재서 품질과 다양성 중 무엇이 무너졌는지 수치로 확인하겠습니다.

대응은 하나씩 바꾸며 비교하겠습니다. 생성자와 판별자의 학습률과 업데이트 균형을 출력을 보며 조정하고, 비포화 손실과 R1, 또는 Hinge 손실과 Spectral Normalization 조합으로 판별자를 안정시키겠습니다. 그리고 판별자가 배치의 다양성을 볼 수 있도록 Minibatch StdDev를 넣고, 데이터가 적다면 ADA를 쓰겠습니다. 비교는 시드 여러 개로 하겠습니다.
