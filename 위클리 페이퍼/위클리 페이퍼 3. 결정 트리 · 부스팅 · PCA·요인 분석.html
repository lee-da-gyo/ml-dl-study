실습 해설

결정 트리의 장점과 단점은 무엇인가요?

한 줄 요약

결정 트리는 불순도를 가장 많이 줄이는 질문을 골라 데이터를 반복해서 나누는 모델이다.

  • 장점: 예측 근거를 규칙 그대로 읽을 수 있다.
  • 단점: 깊어질수록 훈련 데이터를 외우고, 데이터가 조금만 바뀌어도 구조가 달라진다.

그래서 단독으로 쓸 때는 깊이를 제한하고, 성능이 중요하면 랜덤 포레스트나 부스팅 같은 앙상블로 쓴다.

1 · 그림·표·실험
실험 1 깊이를 키우며 과적합과 불안정성 직접 보기 예시 데이터 · 가상의 방문 고객 150명

실제 규칙은 점선(방문 횟수와 체류 시간이 함께 클수록 구매)이고, 경계 근처에는 잡음이 섞여 있습니다. 이 페이지에서 CART(지니 불순도)로 트리를 직접 학습합니다.

  • 깊이를 바꾸면: 영역이 어떻게 쪼개지는지 볼 수 있습니다.
  • 학습 데이터 다시 뽑기를 누르면: 같은 깊이에서도 트리가 얼마나 바뀌는지 볼 수 있습니다.

2 · 핵심 정리와 보충

핵심 트리는 어떤 질문을 고르나

지니 불순도 G = 1 − Σk pk²  ·  엔트로피 H = − Σk pk log₂ pk
고르는 분할 = 부모 불순도 − ( nL/n · 왼쪽 불순도 + nR/n · 오른쪽 불순도 ) 가 가장 큰 분할

모든 특성과 가능한 모든 기준값을 시도해 불순도 감소(정보 이득)가 가장 큰 것을 고르고, 멈춤 조건(최대 깊이, 리프 최소 샘플 수, 순수한 노드)에 닿을 때까지 반복합니다.

예: 구매 8명·미구매 2명인 노드의 지니 불순도는 1 − 0.8² − 0.2² = 0.32이고, 한 클래스만 있으면 0입니다.

정정 · "범주형도 그대로 처리한다"는 구현에 따라 다르다
원래수치형과 범주형 데이터 모두를 처리할 수 있습니다.

정정원리상 트리는 범주로도 나눌 수 있지만, 실제로 범주형을 그대로 넣을 수 있는지는 구현에 따라 다릅니다.

  • ID3·C4.5: 범주마다 가지를 나누는 다중 분할을 씁니다.
  • scikit-learn 결정 트리: 숫자 입력만 받으므로 원-핫이나 순서 인코딩이 필요합니다.
  • LightGBM·CatBoost·HistGradientBoosting: 범주형을 직접 넣을 수 있습니다.

한편 결측값은 scikit-learn 1.3부터 결정 트리가 직접 처리할 수 있습니다. 단, 1.3에서는 splitter="best"이고 기본 분할 기준(분류: gini·entropy·log_loss, 회귀: squared_error·friedman_mse·poisson)일 때만 지원했고, splitter="random"은 1.4부터 지원합니다.

  • 사후 가지치기: 다 키운 뒤 Rα(T) = R(T) + α·|리프 수|가 작아지도록 가지를 자른다. α는 교차 검증으로 고른다.

보충 · 앙상블로 가는 이유

약점이 앙상블의 재료가 된다

깊은 트리는 편향이 작고 분산이 큰 모델입니다.

  • 여러 트리를 평균하면 분산이 준다 (배깅·랜덤 포레스트)
  • 얕은 트리를 순차로 쌓으면 편향이 준다 (부스팅)

Q2로 이어집니다.

결정 트리는 불순도를 가장 많이 줄이는 질문을 골라 데이터를 반복해서 나누는 모델입니다.

가장 큰 장점은 해석 가능성으로, 예측 근거를 if-then 규칙으로 그대로 보여 줄 수 있습니다. 또 스케일링이 필요 없고 비선형 관계와 상호작용도 스스로 잡아냅니다.

단점은 깊어질수록 훈련 데이터를 외우는 과적합과, 데이터가 조금만 바뀌어도 구조가 크게 달라지는 불안정성입니다. 분할이 축에 평행해서 대각선 경계는 계단처럼 근사하고, 학습 범위 밖으로는 외삽하지 못합니다.

그래서 max_depth나 비용 복잡도 가지치기로 규제하고, 성능이 중요하면 랜덤 포레스트나 부스팅으로 확장합니다.

AdaBoost
1995~97		틀린 샘플의 가중치를 키우고, 정확한 학습기에 큰 발언권 α = ½·ln((1−ε)/ε)을 준다. 지수 손실을 최소화하는 것과 같다.원리가 단순하고 스텀프만으로도 성능이 크게 오른다.지수 손실이라 이상치와 잘못된 라벨에 가중치가 폭주한다.잡음이 적은 작은 분류 문제, 원리 학습용
Gradient Boosting (GBM)
Friedman 2001		손실의 음의 기울기를 다음 트리가 학습한다. 미분 가능한 손실이면 무엇이든 쓸 수 있다.회귀·분류·순위 등 손실을 자유롭게 고를 수 있다.기본 구현은 느리고 정규화 기능이 적다.아래 세 구현의 바탕이 되는 개념
XGBoost
Chen & Guestrin 2016		손실을 2차 테일러 근사(기울기 g와 헤시안 h)로 풀고, 목적함수에 리프 수·리프 가중치 벌점을 넣는다. 결측값이 갈 방향을 학습한다.정확도와 안정성이 높고, 희소 데이터·결측값·분산 학습을 지원한다. pandas category 열과 enable_categorical=True로 범주형도 직접 처리한다(tree_method가 hist·approx일 때). 자료와 사례가 많다.하이퍼파라미터가 많다. 깊이 우선(depthwise) 성장이 기본이라 같은 정확도에서 LightGBM보다 느릴 수 있다.정형 데이터의 기본 강자, 안정적인 기준 모델
LightGBM
Microsoft 2017		손실을 가장 많이 줄이는 리프부터 키우는 leaf-wise 성장, 동시에 0이 아닌 일이 드문 희소 특성을 묶는 EFB(기본 사용). 기울기가 큰 샘플 위주로 쓰는 GOSS는 선택 기능이다(4.0부터 data_sample_strategy="goss").대용량·고차원 데이터에서 매우 빠르고 메모리를 적게 쓴다. 범주형도 직접 처리한다.작은 데이터에서 leaf-wise가 한쪽만 깊게 키워 과적합하기 쉽다. num_leaves, min_data_in_leaf 조절이 필수다.수십만 행 이상, 특성이 많고 빠른 반복 실험이 필요할 때
CatBoost
Yandex 2018		범주를 타깃 평균으로 바꿀 때 자기보다 앞 순서의 샘플만 쓰는 Ordered Target Statistics와 Ordered Boosting으로 타깃 누수와 예측 편향을 줄인다. 같은 깊이에서 같은 분할을 쓰는 대칭(oblivious) 트리.범주형 변수를 인코딩 없이 넣을 수 있고, 기본값만으로도 안정적이다. 대칭 트리라 추론이 빠르다.범주형이 많으면 CPU 학습이 상대적으로 느릴 수 있고, 내부 처리가 복잡해 설명하기 어렵다.범주형 변수가 많고, 범주 수가 크며, 튜닝 시간이 적을 때

scikit-learn의 HistGradientBoostingClassifier/Regressor도 LightGBM에서 영감을 받은 히스토그램 방식으로 범주형과 결측값을 직접 처리합니다. 외부 라이브러리 없이 쓸 수 있는 선택지입니다.

2 · 핵심 정리와 보충
정정 · 실습 해설의 부스팅 모델 설명 중 사실과 다른 부분
원래LightGBM 단점: 작은 데이터셋이나 범주형 데이터가 많은 경우에는 성능이 저하될 수 있습니다.

정정두 가지를 나눠서 봐야 합니다.

  • 작은 데이터: leaf-wise 성장 때문에 과적합하기 쉬운 것은 공식 문서에도 있는 단점입니다.
  • 범주형: LightGBM은 categorical_feature로 범주형을 직접 처리하므로 "범주형이 많으면 성능이 떨어진다"고 단정할 수 없습니다.

다만 범주 수가 아주 많고 범주별 데이터가 적을 때는 과적합 위험이 있어 min_data_per_group, cat_smooth로 조절합니다.

원래CatBoost 단점: GPU 설정이 필요할 수 있습니다.

정정CatBoost는 CPU가 기본이고, GPU는 task_type="GPU"로 고르는 선택적인 가속 옵션입니다.

원래정규화(term regularization)와 같은 고급 기능을 추가하여 과적합을 방지

정정영어 용어는 regularization term(정규화 항)입니다. XGBoost는 목적함수에 리프 수에 대한 벌점 γT와 리프 가중치의 L2(λ)·L1(α) 벌점을 더합니다.

보충 XGBoost가 리프 값과 분할을 정하는 식

목적함수 ≈ Σᵢ [ gᵢ·f(xᵢ) + ½·hᵢ·f(xᵢ)² ] + γ·T + ½·λ·Σⱼ wⱼ² (g: 1차 미분, h: 2차 미분, T: 리프 수) 최적 리프 값 wⱼ* = − Gⱼ / (Hⱼ + λ) (Gⱼ, Hⱼ: 리프 j에 속한 g, h의 합) 분할 이득 = ½·[ GL²/(HL+λ) + GR²/(HR+λ) − (GL+GR)²/(HL+HR+λ) ] − γ

λ가 크면 리프 값이 0 쪽으로 줄고, 이득이 γ보다 작은 분할은 하지 않습니다. 제곱 오차에서는 h = 1이라 λ = 0일 때 리프 값이 잔차의 평균이 되어 일반 GBM과 같아집니다.

보충 트리를 키우는 순서: level-wise와 leaf-wise

참고로 XGBoost도 grow_policy="lossguide"로 leaf-wise를 쓸 수 있고, 2.0부터는 히스토그램 방식(tree_method="hist")이 기본입니다. 그래서 히스토그램 자체는 LightGBM만의 차별점이 아닙니다.

LightGBM 이름은 scikit-learn 방식 API 기준입니다(원래 이름: min_data_in_leaf, bagging_fraction, feature_fraction).

실무 순서: 학습률을 0.05~0.1로 두고 조기 종료로 트리 수를 정한 뒤, 트리 복잡도 → 샘플링 → 정규화 순으로 조정합니다.

부스팅은 약한 학습기를 순차적으로 학습시키면서 앞 모델이 틀린 부분을 다음 모델이 보완하는 앙상블입니다. AdaBoost는 틀린 샘플의 가중치를 높이고, 그래디언트 부스팅은 손실의 음의 기울기, 즉 잔차를 다음 트리가 학습합니다.

배깅이 주로 분산을 줄인다면 부스팅은 주로 편향을 줄이고, 트리를 너무 많이 쌓으면 과적합하므로 학습률을 낮추고 조기 종료를 씁니다.

대표 구현은 세 가지입니다. XGBoost는 2차 미분과 정규화 항으로 안정성을 높였습니다. LightGBM은 leaf-wise 성장과 히스토그램·EFB, 선택적으로 GOSS를 써서 대용량 데이터에서 빠르지만, 작은 데이터에서는 num_leaves를 제한해야 합니다. CatBoost는 Ordered Boosting으로 범주형 변수가 많은 데이터에서 타깃 누수를 줄이고, 대칭 트리를 써서 추론이 빠르며 기본값으로도 비교적 안정적입니다.

정정scikit-learn 문서가 말하는 것은 확률적 PCA(PPCA)입니다.

  • 요인 분석의 Ψ를 σ²I로 제한하면 PPCA가 된다 (Tipping & Bishop, 1999)
  • 그 잡음 σ²가 0으로 가는 극한이 일반 PCA다

즉 FA → PPCA → PCA 순으로 가정이 강해집니다.

단위가 큰 변수가 PC1을 차지한다

PCA는 분산이 큰 방향을 찾으므로, 키(cm)와 연봉(원)을 그대로 넣으면 PC1은 거의 연봉이 됩니다. 실험 3에서 PCA 입력을 "원 점수, 수학만 10배"로 바꿔 보세요.

  • 단위가 다르면: 상관행렬(표준화 후 PCA)을 쓴다.
  • 단위가 같고 분산의 크기 자체가 의미 있으면(예: 픽셀 밝기): 표준화하지 않은 공분산 PCA가 맞을 수 있다.

변수들 사이에 공통 요인이 있을 만큼 상관이 있는지 먼저 봅니다.

보충 · 탐색적과 확인적

EFA와 CFA

  • EFA: 몇 개의 요인이 어떤 문항에 걸리는지 데이터에서 찾는다.
  • CFA: "1~5번 문항은 신뢰 요인"처럼 미리 정한 구조가 맞는지 구조방정식으로 검증한다.

척도 개발은 보통 EFA로 찾고, 다른 표본에서 CFA로 확인합니다.

scikit-learn으로 두 방법 실행하기

from sklearn.decomposition import PCA, FactorAnalysis

Z = StandardScaler().fit_transform(X)            # 단위가 다르면 먼저 표준화

pca.explained_variance_ratio_                    # 성분별 설명 분산 비율

PCA와 요인 분석은 둘 다 변수를 적은 차원으로 요약하지만 방향과 목적이 다릅니다.

PCA는 관측 변수의 가중합으로 분산을 가장 많이 보존하는 축을 만드는 계산 기법이라 변수에서 성분으로 가고, 압축이나 시각화, 다중공선성 완화에 씁니다.

요인 분석은 보이지 않는 잠재 요인이 관측 변수를 만든다고 가정하는 통계 모형이라 요인에서 변수로 가며, 공통 분산만 요인으로 설명하고 변수마다 고유 분산을 따로 추정합니다. 그래서 회전을 통해 '언어 능력', '수리 능력'처럼 요인에 이름을 붙이는 해석이 핵심이고, 설문이나 심리 척도 개발에 주로 씁니다.

이론적으로는 고유 분산을 모두 같다고 제한하면 확률적 PCA가 되고, 그 잡음이 0으로 가는 극한이 PCA입니다.

model.fit()이 Keras(TensorFlow)라고 가정할 때 확인 순서대로 쓰는 코드. PyTorch라면 torch.autograd.set_detect_anomaly(True), clip_grad_norm_이 같은 역할입니다.
import numpy as np, tensorflow as tf

# 1) 데이터: NaN·Inf, 라벨 범위, 분산 0 특성
assert np.isfinite(X_train).all() and np.isfinite(y_train).all()
print(y_train.min(), y_train.max())               # 0 ~ num_classes-1 인가?
print((X_train.std(axis=0) == 0).sum())           # 0이 아니면 표준화 때 0으로 나눔

# 2) 처음 NaN·Inf가 생긴 연산에서 바로 멈추기
tf.debugging.enable_check_numerics()

# 3) 분리 실험: 학습률 ↓ + 클리핑, 출력층은 softmax 없이 logits
opt = tf.keras.optimizers.Adam(learning_rate=1e-4, clipnorm=1.0)
model.compile(optimizer=opt,
              loss=tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True))
model.fit(X_train, y_train, callbacks=[tf.keras.callbacks.TerminateOnNaN()])
2 · 핵심 정리와 보충
정정 · from_logits 불일치는 보통 NaN이 아니라 '이상한 loss'로 나타난다
원래 · 작성 답안from_logits 설정 오류: 이미 확률로 변환한 값에 logits용 연산을 적용하거나 그 반대 (NaN의 원인으로 제시)

정정Keras 내장 교차 엔트로피는 확률 입력을 ε으로 잘라 log(0)을 막습니다. 그래서 from_logits 설정이 틀려도 대개 NaN보다는 "loss가 이상하게 크거나 학습이 잘 안 되는" 증상으로 나타납니다.

NaN의 전형적인 원인은 softmax 뒤에 tf.math.log를 직접 쓰는 것처럼 손실을 손으로 구현한 경우입니다. 그래서 내장 손실에 from_logits=True를 쓰는 것이 수치적으로 가장 안전합니다.

보충 · GPU는 조용히 NaN을 낸다

라벨 범위 오류

TensorFlow 문서 기준으로 sparse 교차 엔트로피는 라벨이 클래스 범위를 벗어나면 다음처럼 다르게 동작합니다.

  • CPU: 에러를 낸다.
  • GPU: 에러 없이 해당 행의 loss와 기울기를 NaN으로 낼 수 있다.

버전과 실행 환경(XLA 등)에 따라 다를 수 있으므로, GPU에서만 NaN이 나면 라벨 범위부터 직접 확인합니다.

보충 · FP16에서 사라지는 ε

1e-8은 FP16에서 0이 된다

FP16이 표현하는 가장 작은 양수는 약 6×10⁻⁸이라, Adam의 ε = 1e-8(PyTorch 기본값)은 0으로 반올림됩니다. 분모가 0에 가까워져 폭발할 수 있습니다.

그래서 혼합 정밀도는 가중치와 옵티마이저 상태를 FP32로 유지합니다.

보충 · 클리핑의 한계

이미 Inf가 된 뒤에는 늦다

클리핑은 기울기 노름이 커지는 것을 미리 막는 장치입니다. 노름이 이미 Inf이면 c/Inf = 0, Inf × 0 = NaN이 됩니다.

또 실험 4처럼 학습률이 너무 크면 발산은 막아도 수렴이 느려지므로, 근본 대책은 학습률 조정입니다. PyTorch는 clip_grad_norm_(…, error_if_nonfinite=True)로 바로 알 수 있습니다.

훈련 loss가 줄다가 커지면서 NaN이 됐다면 과적합보다 수치 발산을 먼저 의심합니다. 점점 커졌다는 패턴은 학습률이 안정 한계를 넘었거나 스케줄러로 학습률이 올라간 경우, 또는 기울기 폭발의 전형이라 학습률과 gradient norm 로그부터 봅니다.

동시에 입력과 라벨에 NaN이나 Inf, 범위 오류, 분산이 0인 특성이 없는지 확인하고, TerminateOnNaN과 check_numerics로 처음 NaN이 생긴 배치와 연산을 찾습니다.

그다음 학습률을 낮춘 실험, clipnorm을 건 실험, 혼합 정밀도를 끈 FP32 실험을 하나씩 돌려 어느 조건에서 사라지는지로 원인을 분리합니다. 손실을 직접 구현했다면 log(0)이나 0 나누기도 확인하고, 내장 손실을 from_logits=True로 쓰도록 바꿉니다.

면접 2
면접 · 전문가 답변

고객 만족도 설문 결과(1점~5점)를 예측하는 모델을 만들어야 해요. 회귀로 풀 수도 있고, 5개 범주에 대한 분류로 풀 수도 있어요. 어떤 방식을 선택할 건가요? 각 방식의 장단점을 들어 설명해 주세요.

한 줄 요약

만족도 1~5점은 순서는 있지만 점수 간격이 같다고 보장할 수 없는 순서형 변수다.

  • 둘 중에서는: 큰 오답을 더 크게 벌하는 회귀를 기준 모델로 한다.
  • 가능하면: 순서를 지키면서 간격 가정을 푸는 순서형 회귀를 쓴다.

최종 선택은 MAE·QWK와 비즈니스 목적으로 한다.

1 · 그림·표·실험
실험 5 같은 예측 분포, 어떤 점수를 내놓을까 예시 · 한 고객에 대한 모델의 점수별 확률

모델이 어떤 고객의 점수를 아래 확률로 예상한다고 합시다. 학습 방식에 따라 내놓는 점수가 다릅니다.

  • 회귀(MSE): 평균
  • 5-클래스 분류: 확률이 가장 큰 점수(최빈값)
  • 순서형 모델: 누적 확률로 구한 중앙값

각 선택의 기대 오차를 이 확률로 정확히 계산합니다. 양극화 버튼을 눌러 보세요.

평균 (회귀) 중앙값 (순서형) 최빈값 (분류)
선택 규칙예측기대 MAE기대 RMSE정확히 맞힐 확률

핵심 세 가지 방식 비교

회귀5-클래스 분류순서형 회귀
출력3.72 같은 연속값 하나점수별 확률 5개점수별 확률 5개 (누적 확률에서 계산)
순서 반영반영. 1점을 5점으로 틀리면 크게 벌함반영 안 함. 1→2 오답과 1→5 오답이 같은 벌점반영
간격 가정1↔2와 4↔5의 간격이 같다고 가정가정 없음가정 없음. 경계 θ를 데이터에서 학습
약점MSE로 학습하면 예측이 조건부 평균이라 평균 쪽으로 몰려 1점·5점을 잘 못 낸다. 범위 밖 값(5.3)이 나올 수 있다파라미터가 많고 응답이 적은 점수(보통 1~2점)를 잘 못 배운다비례 오즈 가정이 맞지 않을 수 있고, 구현이 덜 익숙하다
평가 지표MAE, RMSEMacro-F1, 로그 손실MAE, QWK, 로그 손실
순서형 회귀(누적 로짓): P(Y ≤ k | x) = σ(θₖ − wᵀx), θ₁ < θ₂ < θ₃ < θ₄ → P(Y = k) = P(Y ≤ k) − P(Y ≤ k−1)

점수 하나를 만드는 잠재 만족도 wᵀx가 있고, 이 값이 어느 경계 θ 사이에 들어가는지로 점수가 정해진다고 보는 모형입니다. 경계 사이 간격을 데이터에서 따로 배우기 때문에 "1점과 2점 사이는 좁고 4점과 5점 사이는 넓다" 같은 구조를 표현할 수 있습니다.

핵심 평가는 오답의 거리까지 본다: Quadratic Weighted Kappa

κ = 1 − Σ wᵢⱼ·Oᵢⱼ / Σ wᵢⱼ·Eᵢⱼ , wᵢⱼ = (i − j)² / (K − 1)²

표는 실제 i점을 j점으로 예측했을 때의 벌점 w입니다. 1점을 5점으로 틀리면 1점을 2점으로 틀린 것보다 16배 크게 벌합니다.

O는 실제 혼동행렬, E는 우연히 맞힐 때의 기대 혼동행렬이라 κ = 1이면 완벽, 0이면 우연 수준입니다. scikit-learn에서는 cohen_kappa_score(y, y_hat, weights="quadratic")입니다.

2 · 핵심 정리와 보충
보충 · 회귀를 쓴다면

반올림 대신 경계를 학습한다

회귀 예측값을 1.5, 2.5, 3.5, 4.5에서 자르면 평균 쪽 쏠림이 그대로 남습니다.

경계 4개를 검증 데이터나 교차 검증의 OOF 예측에서 QWK가 가장 커지도록 따로 최적화하면 1점·5점도 낼 수 있습니다. 테스트 데이터로 경계를 정하면 누수입니다.

보충 · 순서형 구현 방법

통계 모형부터 신경망까지

  • 통계: 누적 로짓 (statsmodels OrderedModel)
  • 트리·일반 분류기: "Y > 1?", "Y > 2?" … 이진 분류 4개로 나누는 Frank & Hall 방식
  • 신경망: 출력층을 누적 확률로 바꾸는 CORAL·CORN
보충 · 목적이 답을 바꾼다

불만 고객 찾기가 목표라면

점수를 맞히는 것보다 1~2점 고객을 놓치지 않는 것이 중요하다면, "1~2점 vs 3~5점" 이진 분류로 재현율을 기준으로 평가하는 편이 맞을 수 있습니다.

1~2점은 보통 응답이 적으므로 층화 분할과 클래스 가중치가 필요합니다.

회귀 기준 모델과 순서형 회귀를 같은 지표로 비교하기
import numpy as np
from sklearn.metrics import mean_absolute_error, cohen_kappa_score
from statsmodels.miscmodels.ordinal_model import OrderedModel

# 회귀: 연속값 → 경계로 1~5점 변환 (경계는 검증 QWK가 최대가 되도록 조정)
cuts = [1.5, 2.5, 3.5, 4.5]
y_reg = np.digitize(reg.predict(X_val), cuts) + 1

# 순서형 회귀: 누적 로짓 (X에 상수항을 넣지 않는다)
res = OrderedModel(y_tr, X_tr, distr="logit").fit(method="bfgs", disp=False)
y_ord = np.asarray(res.predict(X_val)).argmax(axis=1) + 1   # MAE가 목표면 중앙값을 쓴다

for name, p in [("회귀", y_reg), ("순서형", y_ord)]:
    print(name, mean_absolute_error(y_val, p),
          cohen_kappa_score(y_val, p, weights="quadratic"))

고객 만족도 1~5점은 순서는 있지만 1점과 2점의 간격이 4점과 5점의 간격과 같다는 보장이 없는 순서형 변수입니다.

회귀는 순서와 오차 크기를 반영해 1점을 5점으로 틀리면 크게 벌하지만, 간격이 같다고 가정하고, MSE로 학습하면 예측이 평균 쪽으로 몰려 1점이나 5점을 잘 못 맞힙니다. 5-클래스 분류는 점수별 확률을 주고 양극화된 분포도 표현하지만, 1점을 2점으로 틀린 것과 5점으로 틀린 것을 똑같이 취급합니다.

그래서 둘 중 고르라면 회귀를 기준 모델로 두고, 실제로는 누적 로짓 같은 순서형 회귀를 쓰겠습니다. 평가는 MAE와 Quadratic Weighted Kappa, 점수별 재현율로 하고, 목적이 불만 고객 조기 발견이라면 1~2점 재현율을 기준으로 최종 결정하겠습니다.
